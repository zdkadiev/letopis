## 1. Summary
letopis — персистентная общая память AI-агентов одного проекта. Сначала проверяем её на coding-задачах; дальнейшее использование организационными агентами остаётся перспективой. Агент сохраняет знания в читаемых документах, находит релевантные фрагменты и следует связям между ними. Выбран локальный инструмент: агенты правят документы напрямую, letopis проверяет их и строит производный поиск, без обязательного внешнего сервиса. [D-1](decisions.md#D-1), [D-21](decisions.md#D-21), [D-93](decisions.md#D-93).

## 3. Problem
[known] Между сессиями теряются найденные факты и основания решений, которые агенту нужны в следующей задаче. [known] Требуется общая память, а не отдельная история каждого агента. [unknown] Размер выигрыша на реальных задачах пока не измерен. Успех — меньше повторного исследования при сохранении корректности работы.

## 4. Users
Первичный пользователь — coding-агент; разработчик задаёт задачу, решения и явные команды сохранения. Агент сам подбирает контекст, читает найденные документы и перепроверяет устаревшие знания. Иные агенты организации — следующий горизонт; распределённая организация пользователей и их права в v1 не проектируются.

## 6. Evaluation
Сильная сторона выбранного подхода — читаемые исходные знания и явные связи/происхождение, доступные нескольким агентам. Это следствие выбранной модели, а не измеренный результат. Главные затраты — дисциплина разметки, корректная конкуренция и восстановление, стоимость локального семантического поиска. Причины возможной неудачи: поиск не экономит исследование; устаревшие основания вводят агента в заблуждение; локальные модели не помещаются в доступные ресурсы. Проверки этих рисков не заменяются миграцией документов.

Первая проверка сравнивает одинаковые цепочки реальных связанных coding-задач одного репозитория тем же агентом с letopis и без накопленной межсессионной памяти. Между задачами начинаются новые сессии; знания из предыдущей работы нужны для следующих задач. [D-26](decisions.md#D-26). Оцениваем пользу памяти целиком по трём прежним критериям, при сохранении корректности результата. Сравнение с отдельным вариантом обычных Markdown-заметок для первой проверки не выбрано. [D-25](decisions.md#D-25). Это выбор исходной точки, а не результат эксперимента и не утверждение остальных условий теста.

Для первой проверки выбран Letopis, [D-27](decisions.md#D-27). В текущей найденной рабочей копии доступны проектные документы и исследовательские пробы; результат проверки на реальной цепочке coding-задач ещё не получен. Память letopis начинает испытание без заранее подготовленных знаний; агент накапливает её по ходу задач, и она сохраняется между сессиями, [D-28](decisions.md#D-28). Конкретные задачи и методика измерений относятся к подготовке пилота P-1. По [D-33](decisions.md#D-33) процент улучшения до первого пилота не фиксируется; целевые значения уточняются по его результатам. Высокоуровневый сценарий первой проверки определён; это не означает, что испытание уже проведено.

## 7. Scope
В v1: общая долговечная память, поиск ссылок, обход связей/вложенности, проверка правок корпуса, перепроверка происхождения, обслуживание индекса и диагностика. Атомарные группы правок нескольких файлов в v1 не входят, [D-93](decisions.md#D-93). Вне v1: распределённый доступ, несколько рабочих копий, ACL, перенос старого корпуса, отдельные сетевые интерфейсы. Продукт не изменяет исходный код как память и не возвращает полные тексты через поиск. [D-21](decisions.md#D-21).

## 8. Approaches
| Подход | Возможность | Ограничение | Статус |
|---|---|---|---|
| Общие документы без проверки и индекса | Минимальная организация заметок | Нет проверки целостности, поиска и происхождения | Не выбран |
| Документы с прямыми правками, проверкой и производным поиском | Читаемые знания, явное происхождение, проверка при каждом вызове | Нет атомарности многофайловых правок | Выбран, [D-93](decisions.md#D-93) |
| Документы с управляемой записью через CLI | Атомарные группы и откат | Собственный протокол записи и восстановления | Был выбран (D-2), заменён [D-93](decisions.md#D-93) |
| Централизованный удалённый сервис | Можно расширять за пределы одной машины | Выходит за локальную границу v1 | Вне v1 |

Это сравнение формы уже выбранного решения; проверки конкурентных продуктов здесь не заявляются.

## 9. System concept
letopis хранит общее проектное знание в размеченных документах. Агент начинает задачу с поиска, получает ссылки на конкретные фрагменты, читает их сам и при необходимости обходит связи или включённость. По завершении исследования он сам записывает решение в размеченный документ вместе с источниками и основанием, по которому его проверил; letopis проверяет разметку и связи и делает знание находимым при следующем вызове. Если источники изменились, знания остаются доступны с признаками необходимости перепроверки.

Управление документами отвечает за чтение и проверку корпуса, поиск — за подбор ссылок, индексирование — за производные поисковые представления, проверка источников — за сопоставление оснований. Это роли одного локального инструмента. Канонические документы и их прошлое содержимое доступны отдельно от поисковых структур. Git остаётся внешним инструментом версионирования; вычисление embeddings подключаемо и может отставать от сохранения, при этом текстовый поиск работает. Важнее всего корректность знаний/записи, локальная самостоятельность и ограниченная сложность решения. [D-7](decisions.md#D-7), [D-11](decisions.md#D-11), [D-19](decisions.md#D-19), [D-24](decisions.md#D-24).
