# R-10: чем Letopis отличается от памяти для coding agents?

> **Дата:** 2026-11-02 · **Запрос:** сравнение похожих систем и преимуществ Letopis · **Решение:** позиционирование продукта · **Статус:** свежая проверка; возможности конкурентов перепроверять перед публикацией сравнений.

## Вопрос

Какие свойства Letopis уже есть у близких систем, а какую комбинацию можно обоснованно предлагать разработчикам как преимущество?

## Факты

Уверенность относится к прочитанному документированному контракту, а не к независимому испытанию продукта. Ветки разработки могут опережать релизы.

**Неопределённости и расхождения.** Не найден документированный эквивалент всей модели независимых Git tree оснований Letopis у рассмотренных конкурентов; это не доказательство отсутствия. Наличие Git, истории заметок, checksums заметок или времени факта не доказывает такую модель. Kage уже опровергает широкое заявление «только мы замечаем устаревание относительно кода». Проверка файлов сама по себе не доказывает истинность утверждения. Репозиторий преемника Cipher архивирован; актуальность поддержки требует проверки.

## Что это значит для нас

**Основное отличие — сочетание Git-оснований знаний и управляемой перепроверки в распределённом Markdown-графе.** Это обоснованное позиционирование, но не доказанная мировая уникальность.

1. Каждое знание может сохранять основание из своей версии кода. Старое архитектурное решение и новое описание API сосуществуют с проверяемыми разными основаниями. Польза: различать исторический контекст и сведения о текущем коде.
2. Изменение кода отмечается для пересмотра, а не объявляется автоматическим опровержением. В отличие от описанного Kage recall, Letopis сохраняет запись и позволяет явно выбирать `needs_recheck` и `source_revisions`. Польза зависит от соблюдения агентом политики использования флагов.
3. Размеченные знания можно держать рядом с соответствующим кодом и существующими документами, без переноса в обязательную отдельную папку памяти. Связи задаются явно. Само по себе свободное размещение не уникально: Basic Memory и QMD тоже настраивают каталоги.
4. Локальный CLI с производным индексом не требует LLM для авторской разметки, проверок и полнотекстового поиска. Эта полезная характеристика также встречается у конкурентов.

**Ограничения преимущества.** Markdown, граф, Git, локальность, поиск и память между сессиями по отдельности уже распространены. У конкурентов документированы готовые MCP-интеграции, onboarding и автоматический capture/recall. Letopis сейчас опирается на CLI и skill; ручная разметка и запись корректного `source_snapshot` требуют дисциплины. Более быстрый поиск, меньше токенов и меньше ошибок не установлены сравнительным экспериментом.

Проверяемая гипотеза: агент с Letopis точнее различает знания для разных ревизий кода. Проверить одинаковые задачи по двум Git-версиям, изменения кода и последующую перепроверку против Basic Memory и Kage. Измерять ошибки, успешность задач, токены и время.

Позиционирование: «Память проекта с проверяемой привязкой каждого знания к версии исходного кода».
