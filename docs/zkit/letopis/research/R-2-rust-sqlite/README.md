# Исследовательская проба Rust и SQLite

Программа проверяет rusqlite, FTS5 и vec1. Это диагностический код, не реализация Engram. Выводы и ограничения находятся в [отчёте](../R-2-rust-sqlite.md).

Используются rustc/cargo 1.95.0, rusqlite 0.40.2, libsqlite3-sys 0.38.2, встроенная SQLite 3.53.2. Cargo.lock закрепляет зависимости. Проверенный target — aarch64-apple-darwin; Linux-запуска здесь нет.

Аргументы программы: новый путь для её тестовой БД, путь к временной Go-БД с таблицей `big` из 50 000 векторов размерности 384, путь к собранному vec1. Программа отвергает занятый путь новой БД и открывает исходную Go-БД только для чтения. Не передавайте ей служебную БД проекта.

Библиотека vec1 должна быть собрана по инструкции [Go-пробы](../R-1-go-sqlite/README.md). Используется тот же закреплённый исходник 0.8 из официального зеркала SQLite и стандартный entry point `sqlite3_extension_init`; SHA-256 исходника и библиотеки указаны в build-manifest.json.

Для воспроизведения скопируйте эту папку во временный каталог. Подготовьте временную Go-БД, запустив нативную Go-пробу на свободном пути с количеством 50000. Затем соберите Rust-пробу:

```sh
cargo build --release --locked
```

Пример запуска с подготовленным набором и новой тестовой БД:

```sh
./target/release/engram-rust-sqlite-probe /private/tmp/engram-rust-repeat.db /private/tmp/engram-go-dataset.db /private/tmp/vec1.dylib
```

Для нового запуска выбирайте новый путь выходной БД. Значения результатов можно сравнивать с `results.txt`, но точные времена зависят от системы и фоновой нагрузки. Вектор запроса берётся из строки rowid=1; он отличается от query-вектора первоначального Go-замера, поэтому это не строгий benchmark языков.

Проверки качества выполнены командами:

```sh
cargo clippy --release --locked -- -D warnings
cargo fmt -- --check
```

Сигнал отмены в диагностике генерируется из другого потока после паузы 1 мс. Это не реализация SIGINT и не продуктовый таймаут. Сохранены 10 отметок check=PASS и итог complete=PASS; программа завершилась кодом 0.
