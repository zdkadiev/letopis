# R-5: Git-хранение синтетических файловых версий

> **Date:** 2026-10-18 · **Asked by:** resource-math, P-2 · **Feeds decision:** D-52; оценка диска · **Status:** fresh — синтетика, небольшой масштаб

## Question
Сколько занимают версии Markdown и служебные ссылки до/после штатной упаковки Git; остаются ли все снимки читаемыми?

## Findings
macOS 26.6.2 arm64, Git 2.50.1 (Apple Git-155), SHA-1 object format и файловое хранение refs в тесте. Созданы два независимых временных репозитория с одинаковым начальным корпусом: 30 файлов × 30 элементов × 2000 ASCII-байт = 1,8 МБ. Каждый файл — 60 КБ. В каждом варианте 200 правок по пять разных файлов, 1000 новых файловых версий суммарным логическим объёмом 60 МБ, плюс исходный корпус.

- **point:** меняются десять цифр значения внутри одного элемента.
- **rewrite:** текст одного элемента регенерируется из словаря; его ID и служебная обвязка сохраняются.
- В обоих случаях записывается новая полная версия файла. На каждый снимок создана отдельная ссылка на tree; коммитов нет.

| Метрика, МБ (10⁶ байт) | point | rewrite |
|---|---:|---:|
| Объекты Git до repack: сумма размеров файлов | 15,687 | 15,603 |
| Объекты Git после repack: сумма размеров файлов | 0,614 | 1,318 |
| Файлы всей .git до упаковки: сумма выделенных блоков | 18,534 | 18,534 |
| После repack объектов: сумма выделенных блоков файлов .git | 1,475 | 2,179 |
| После дополнительного pack-refs: то же | 0,668 | 1,372 |

После `git repack -a -d` все 1231 объект (1030 blob + 201 tree) и 201 ссылка сохранены в каждом репозитории. Все байты объектов проверены до и после упаковки по исходным SHA-256 и Git OID; значения ссылок сверены со снимками. `git fsck --full --strict --no-reflogs` завершился с кодом 0.

201 отдельный файл refs занимал 823 296 байт выделенных блоков. После `git pack-refs --all` ссылки находились в packed-refs размером 14 719 байт, с 16 384 байтами выделенных блоков; все ссылки и все объекты повторно проверены. Логический размер .git при этом немного вырос из-за более длинных записей packed-refs, а сумма выделенных блоков уменьшилась. Измерения логических байтов и блоков нельзя подменять друг другом.

Основная проба — 38,109 с; дополнение — 0,522 с; всего активного выполнения 38,631 с. Объектная упаковка заняла 0,235 / 0,417 с. Это время на маленьком тёплом наборе, не прогноз обслуживания годового объёма.

## What it means for us
3,15 ТБ из модели — поток несжатых полных файловых версий; он не означает такой же занятый диск. В этой синтетике объекты и ссылки существенно уплотняются штатными средствами Git, снимки остаются доступными. Новое собственное хранилище истории из этих результатов не следует.

Коэффициент нельзя переносить на год как measured-вход: словарь, энтропия, доля переписанного текста, повторяемость, размер/раскладка корпуса и количество refs отличаются от реальных. Начальный корпус включён в итоговые размеры; это не чистая цена одной новой версии. Периодическая упаковка в продукте не утверждена, а непакованные объекты и временное место при обслуживании могут менять дисковый пик. Исходный код внешних источников, бэкапы, SQLite, FTS, vec1 и очередь в этой пробе отсутствуют.

Сумма st_blocks × 512 относится только к файлам; каталоги, полное устройство/APFS, снимки ФС и свободное место не измерялись. Не проверялись сбои питания, конкурентные записи, 100 000 узлов, миллионы refs или реальные агенты. P-2/P-3 не закрыты.

## Method
D-52 разрешает пробу; sub-agents не использовались. Зафиксирован генератор со случайными числами от постоянных seed и ограниченным словарём. Глобальная/системная конфигурация Git исключена, auto GC/maintenance в тесте отключены; упаковка запускалась явно. Запись через hash-object, update-index, write-tree, update-ref, без коммитов и без реализации Engram.

[Артефакты и скрипты](R-5-git-storage-probe/README.md): размеры, время, manifests объектов и снимков, исходный генератор. Рабочий Letopis не изменялся, кроме сохранения документов.

Главный агент открыл официальные [repack](https://git-scm.com/docs/git-repack), [pack-objects](https://git-scm.com/docs/git-pack-objects) и [pack-refs](https://git-scm.com/docs/git-pack-refs): смысл штатных операций подтверждён; численные результаты взяты из локального замера.
