# R-4: Первый локальный замер Ollama embeddings

> **Date:** 2026-10-18 · **Asked by:** resource-math, P-2 · **Feeds decision:** D-49; ресурсные оценки · **Status:** fresh — одно оборудование, короткая синтетическая проба

## Question
Каковы задержки embedding API и наблюдаемая память расчётной модели на текущем Mac?

## Findings
Среда: Apple M4 Pro, 14 ядер CPU, 51 539 607 552 байта ОЗУ (48 ГиБ), macOS 26.6.2 arm64; Ollama 0.40.6. Модель embeddinggemma:300m-qat-q4_0, manifest digest `101341d65c2ccbf23f16650b79d30b9fca94a45ffa09a9984c600157b81a58df`, слой весов из R-3. CLI показывает 100% GPU, runner llamacpp, контекст 2048, размерность 768.

| Наблюдение | Результат | Доказательство |
|---|---|---|
| Первый вызов с незагруженной моделью, документ 2 КБ | 1 033,85 мс; load_duration API 806,90 мс | requests.jsonl; before_ps пуст |
| Прогретые короткие запросы, 10 вызовов | медиана 8,39 мс; максимум 9,20 мс | requests.jsonl |
| Смешанные запросы | 150/150 успешны; медиана 35,13 мс; p95 48,71 мс; максимум 133,32 мс | summary.json |
| Смешанные документы по 2 КБ | 25/25 успешны; медиана 73,57 мс; p95 98,94 мс | summary.json |
| Память: сумма RSS процессов, выборки каждые 0,5 с | до загрузки 139,25 МБ; наблюдаемый максимум 577,27 МБ; после нагрузки 576,80 МБ | memory.json |
| Размер модели, заявленный API ps | size и size_vram по 302,30 МБ; это не RSS | metadata.json |

Смешанная проба подавала 10 коротких запросов/с и 100 документов/мин в течение примерно 15 секунд. Отправлено 175 запросов без пропусков клиентом; максимальная задержка отправки 11,03 мс. Это выдержанный короткий входящий поток, не максимальная пропускная способность или длительный тест. Всего вместе с одиночными вызовами — 204/204 успешных ответа, по одному конечному нормированному вектору размерности 768. Общая проба заняла 21,00 с; отдельная сетевая загрузка — 1 450,40 с.

Для каждого размера и языка выполнено по три последовательных вызова:

| Байты UTF-8 | Медиана EN / RU, мс | Входные токены EN / RU |
|---|---|---|
| 500 | 11,37 / 10,77 | 88 / 92 |
| 2000 | 24,76 / 24,40 | 331 / 350 |
| 8000 | 85,46 / 86,31 | 1304 / 1385 |

Первый 500-байтный EN-вызов после загрузки занял 123,92 мс; он не исключён из данных. Значения p95 рассчитаны nearest-rank; малые группы не дают статистической SLA.

## What it means for us
На этом Mac модельная часть выдержала проверенный поток. Это не измерение search с FTS/vec1 и не подтверждение NFR-2/NFR-3/NFR-4 на ноутбуке с 4 ГБ или CPU без GPU.

Пиковая сумма RSS включает runner 437,60 МБ, сервер 40,76 МБ и приложение Ollama 98,91 МБ. RSS может повторно учитывать общие страницы; GPU и общая память macOS учтены неполно, краткие пики могли остаться между выборками. Нельзя складывать RSS с size_vram или считать остаток от 1 ГБ доступной памятью будущего Engram. Нужен полный замер приложения с БД/индексами на целевом оборудовании.

Все выбранные синтетические тексты 8 КБ поместились в контекст с `truncate:false`; это не гарантия для произвольного Markdown такого размера. Качество retrieval не измерялось. Параметры resource-math/model.py пока не заменяются этими числами: они описывают другой масштаб и ресурсы.

## Method
D-49 разрешает пробу; исследовательские sub-agents для локального измерения не использовались. Глобальные настройки не менялись, чужие модели не выгружались; API ps был пуст до начала, после содержал только выбранную модель. Остальные приложения Mac работали; изоляции, CPU-only пробы и оценки фоновой конкуренции нет. RSS собран через ps; hardware через sysctl; клиентские задержки — monotonic clock вокруг HTTP-вызова, включая сериализацию/чтение ответа. Вычисления вне транзакций продукта, сам продукт не реализовывался.

Документация проверена главным агентом: [embed](https://docs.ollama.com/api/embed) — truncate и единицы duration; [ps](https://docs.ollama.com/api/ps) — поля модели. Источник чисел — локальные артефакты, не внешние бенчмарки.

[Исходные данные и скрипт](R-4-ollama-local-probe/README.md). Скрипт сохранён как исполнен; для повтора нужен новый каталог вывода и исходно незагруженная модель. Повтор на другом оборудовании — новый набор данных.
