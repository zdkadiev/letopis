# Engram 2.0 — Rust и сравнение с Go

Дата проверки: 12 октября 2026 года. По итогам исследования пользователь выбрал Rust, rusqlite и нативный vec1 для реализации Engram 2.0. Рекомендуется минимальная обвязка без ORM и обязательного async-слоя. Согласованные SQLite, WAL + FULL, fullfsync на macOS, FTS5 contentless-delete, Markdown/Git и CLI-контракты сохраняются. Конкретные версии, режим vec1 и организация соединений уточняются отдельно; выбор стека не подтверждает готовность продукта.

Rust даёт управление памятью через ownership без сборщика мусора и явное владение ресурсами. Для самого векторного поиска это не означает автоматического выигрыша: Rust и нативный Go-вариант вызывают тот же C-код vec1. Выбор следует делать по устройству всего приложения, стоимости разработки и измеренному бюджету памяти. Основания: [Rust ownership](https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html) и [предыдущая Go-проверка](R-1-go-sqlite.md).

## SQLite библиотеки для Rust

| Вариант | Что обеспечивает | Оценка для первой версии |
|---|---|---|
| `rusqlite` | Прямой синхронный SQLite API, транзакции, PRAGMA, загрузка расширений, InterruptHandle | Выбран: соответствует локальной БД и позволяет явно контролировать соединения |
| `sqlx` | Async-интерфейс, пул, SQLite и другие БД, подключение расширений при открытии | Подходит при выбранной async-архитектуре; для одной локальной SQLite добавляет обвязку |
| `libsql` | API к движку на основе SQLite, локальные БД и возможности репликации | Для согласованной V1 не даёт необходимой функции, ради которой следует менять обычную SQLite |

Основания: [rusqlite](https://docs.rs/rusqlite/0.40.2/rusqlite/), [SQLx connection](https://docs.rs/sqlx/latest/sqlx/sqlite/struct.SqliteConnection.html), [SQLx extension options](https://docs.rs/sqlx/latest/sqlx/sqlite/struct.SqliteConnectOptions.html), [libsql](https://docs.rs/libsql/latest/libsql/). Практическая проба ниже относится к rusqlite; SQLx и libsql здесь не запускались.

SQLx выполняет блокирующие вызовы SQLite в отдельном потоке и обменивается с ним через каналы. Async не делает операции SQLite неблокирующими на уровне движка и не добавляет писателей. Для нашего асинхронного индексирования достаточно отделить фоновую работу от CLI; это не обязывает вводить async/await во все доменные и прикладные интерфейсы.

## Минимальное подключение rusqlite и vec1

Проверена `rusqlite 0.40.2`, `libsqlite3-sys 0.38.2`, встроенная SQLite `3.53.2`. Версия движка удовлетворяет принятому порогу `3.51.3+`. В пробе использованы только features `bundled` и `load_extension`; `bundled-full`, ORM и runtime не потребовались.

```toml
[dependencies]
rusqlite = { version = "=0.40.2", default-features = false, features = ["bundled", "load_extension"] }
```

`bundled` собирает SQLite из поставляемого C-исходника через C-компилятор, а не использует случайную системную библиотеку. В проверенной сборке FTS5 включён через `SQLITE_ENABLE_FTS5` в `libsqlite3-sys/build.rs`; contentless-delete дополнительно проверен запуском. Версию всё равно следует контролировать в готовом приложении через `sqlite_version()`. Основания: [Cargo features rusqlite](https://github.com/rusqlite/rusqlite/blob/v0.40.2/Cargo.toml) и [сборка libsqlite3-sys](https://github.com/rusqlite/rusqlite/blob/v0.40.2/libsqlite3-sys/build.rs).

Рабочий способ регистрации vec1 на каждом новом соединении:

```rust
use rusqlite::{Connection, LoadExtensionGuard};

let conn = Connection::open(path)?;
// SAFETY: extension_path points to the bundled, verified vec1 binary.
unsafe {
    let _guard = LoadExtensionGuard::new(&conn)?;
    conn.load_extension(extension_path, Some("sqlite3_extension_init"))?;
}
conn.pragma_update(None, "journal_mode", "WAL")?;
conn.pragma_update(None, "synchronous", "FULL")?;
conn.pragma_update(None, "fullfsync", true)?;
```

Это фрагмент исследовательской инициализации, не новый CLI-контракт. `LoadExtensionGuard` отключает возможность загрузки расширений при выходе из области действия. `unsafe` необходим, поскольку загрузка исполняет нативный код; путь относится к поставке приложения. После регистрации используются обычные SQL-запросы и BLOB-параметры. Основание: [LoadExtensionGuard в исходнике rusqlite](https://github.com/rusqlite/rusqlite/blob/v0.40.2/src/load_extension_guard.rs).

Для первоначальной проверки использована та же macOS ARM64 `.dylib`, что в Go-пробе: vec1 `0.8`, NEON, multi-threaded. Заголовки SQLite, формат векторов, архитектура, SIMD и версия расширения требуют такого же контроля, как в Go. Статическое включение C-кода через build.rs также возможно как отдельный способ поставки, но здесь не проверялось. Преимущество «один бинарник» не следует автоматически приписывать языку: первоначальная проверка использовала отдельную библиотеку расширения.

## Результаты временной Rust-пробы

Среда: rustc/cargo `1.95.0`, macOS ARM64, release-сборка. Все создаваемые БД и артефакты находились во временном каталоге; документы и служебная БД проекта не использовались. При открытии двух соединений проверены WAL, synchronous=2 (FULL), fullfsync=1 и foreign_keys=1.

| Проверка | Результат |
|---|---|
| FTS5 contentless-delete | Совпадение найдено, text возвращает NULL, DELETE удаляет совпадение |
| Два соединения и повторное открытие | vec1 зарегистрирован и выполняет поиск |
| UPDATE без commit | Выход из области Transaction откатывает изменение вектора |
| Писатель при активной read-транзакции | Прежний читатель сохраняет старый вектор и результат, новый видит обновление |
| Фильтр после K=1 | Без streaming — 0 результатов, со streaming — правильный результат |
| Прерывание core SQL, векторного поиска и flat rebuild | Получен SQLite OperationInterrupted |
| После отменённой перестройки | Сохранены 50 000 векторов, поиск снова работает |

Для измерения взяты ровно те 50 000 векторов размерности 384, которые были сгенерированы Go-пробой. Они прочитаны из её временной БД и вставлены в отдельную Rust-БД; исходная БД открывалась только для чтения. Вектор запроса — первый сохранённый вектор; пять запросов вернули по 10 соседей с первым rowid=1.

Перестройка flat/cos заняла 436 мс, пять поисков — 12,0–16,8 мс. Прерываемые операции, при запросе interrupt из другого потока после паузы 1 мс, завершились за 1,57–1,64 мс от начала пробы. Это не продуктовый таймаут и не гарантия задержки обработки SIGINT.

Нативная Go-проба ранее дала 11,8–16,6 мс на таком количестве и размерности векторов. Этот результат показывает одинаковый порядок времени, но не является строгим сравнением языков: SQLite 3.53.2 против 3.53.4, разные query-векторы, нет p95/p99 и общей нагрузки. Копирование набора в Rust заняло около 3 секунд и включало чтение исходной БД; сравнивать это с чистой вставкой Go было бы некорректно.

В результаты не включены вычисление embedding запроса, текстовый поиск, полные графовые фильтры и гибридное ранжирование. Бюджет 4 ГБ, десять агентов, ANN-обучение, потеря питания и Linux-запуск не проверены. Установлен только target aarch64-apple-darwin; другие Rust-targets не добавлялись. `cargo build --release --locked`, `cargo clippy --release --locked -- -D warnings` и `cargo fmt -- --check` прошли.

## Что Rust меняет в устройстве приложения

Ownership и RAII позволяют задавать явную жизнь буферов, statements, транзакций и снимков чтения. Вектор, прочитанный как `Vec<u8>`, можно передать далее без обязательного преобразования в `Vec<f32>` и обратно; при декодировании необходимо сохранять согласованный float32-формат. Экономия копирования зависит от реализации и должна измеряться, а отсутствие GC не ограничивает само по себе число выделяемых буферов или память моделей.

`rusqlite::Connection` имеет Send, но не Sync: соединение можно передать работнику, однако нельзя параллельно использовать его через обычные общие ссылки. Разные читатели могут владеть отдельными соединениями, а короткие записи по-прежнему сериализуются SQLite. Один mutex вокруг всех чтений и записей упростил бы код, но заставил бы длительный поиск задерживать остальных агентов. Окончательное число соединений и модель работников выбираются отдельно. Основание: [Connection и её trait implementations](https://docs.rs/rusqlite/0.40.2/rusqlite/struct.Connection.html).

DDD и hexagonal сохраняются: доменная модель может использовать struct/enum, прикладные сервисы — обычные функции/типы, порты — traits, адаптеры — rusqlite, файловая система, Git и embedding runtime. Для реализации этих границ не требуется отдельный DDD-framework. Сам граф продолжает храниться как nodes/edges с ID; связность не требует построения самоссылочных Rust-объектов.

Цена такого контроля — явное проектирование владения, времени жизни и передачи задач. Если команда хорошо знает Go и только осваивает Rust, это реальная дополнительная сложность. В текущем репозитории продуктового кода ещё нет, поэтому смена кандидата сейчас не означает переписывание реализации.

## Дополнительные библиотеки как кандидаты

| Задача | Кандидат | Зачем подходит и что ещё проверить |
|---|---|---|
| Команды CLI | [clap](https://docs.rs/clap/latest/clap/) | Разбор команд и флагов; ошибки нужно привести к нашему JSON и кодам 0/1 |
| JSON | [serde](https://docs.rs/serde/latest/serde/), [serde_json](https://docs.rs/serde_json/latest/serde_json/) | Типизированные входы/выходы; требуется согласованное отклонение неизвестных полей |
| JCS | [serde_json_canonicalizer](https://docs.rs/serde_json_canonicalizer/latest/serde_json_canonicalizer/) | Кандидат для RFC 8785; нужен набор общих эталонных случаев для хешей |
| Markdown | [pulldown-cmark](https://docs.rs/pulldown-cmark/latest/pulldown_cmark/struct.Parser.html) | События и диапазоны исходного текста; служебная разметка Engram требует собственного слоя |
| Git | [git2](https://docs.rs/git2/latest/git2/struct.Repository.html) либо внешний Git через процесс | Доступ к blobs/trees/refs; внешнего Git достаточно как первого кандидата, внедрение libgit2 не обязательно |
| Локальные embeddings | [Candle BERT](https://docs.rs/candle-transformers/latest/candle_transformers/models/bert/index.html) или [ort](https://docs.rs/ort/latest/ort/) | Candle имеет модель BERT, ort связывает ONNX Runtime; нужна проверка выбранной модели и оборудования |

Эти библиотеки изучены по документации, но не включены в продукт и не проверены этой SQLite-пробой. Локальный embedding-адаптер должен работать с заранее доступными весами и tokenizer без сетевой загрузки в ходе работы. Нужно проверить pooling, нормализацию и совпадение векторов с выбранной моделью. Наличие библиотеки inference не подтверждает выполнение требований по памяти и качеству.

## Подводные камни

### Отмена должна доходить до SQLite

`Connection::get_interrupt_handle()` возвращает handle для вызова `interrupt()` из другого потока. Он проверен в пробе. В продукте SIGINT или reindex --cancel должен передаваться текущей операции и её соединению; поздний сигнал не должен прерывать следующую задачу на переиспользованном handle. Проба дожидается завершения потока отмены перед дальнейшим использованием соединения. Основания: [InterruptHandle](https://docs.rs/rusqlite/0.40.2/rusqlite/struct.InterruptHandle.html) и [SQLite interrupt](https://www.sqlite.org/c3ref/interrupt.html).

Если использовать Tokio, `spawn_blocking` не позволяет остановить уже начавшийся блокирующий вызов через abort. Обёртка async/future не заменяет InterruptHandle или совместную проверку отмены. Внешние embedding runtimes также требуют собственного механизма остановки или завершения безопасной порции работы. Основание: [Tokio spawn_blocking](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html).

### RAII не заменяет восстановление после сбоя

Откат Transaction при выходе из scope полезен при обычной ошибке. При остановке процесса, потере питания или abort нельзя рассчитывать на выполнение Drop. Прикладная запись восстановления, Git-снимок, долговечное сохранение файлов и финальная транзакция БД остаются по прежнему протоколу. Настройки panic/unwind сами по себе не делают файловую правку атомарной. Основание для режимов panic: [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html).

### JSON по умолчанию не является JCS

Обычный `serde_json` не подменяет согласованную каноникализацию перед SHA-256. Порядок ключей, числа и строки должны соответствовать [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785). Для файлов и элементов хешируются прежние точные байты, а не текст после Markdown-рендеринга. Подмена алгоритма хеша при смене языка недопустима.

У clap `parse()` сам завершает процесс при ошибке. Для нашего CLI предпочтителен `try_parse()` с переводом ошибки в единый JSON-ответ; стандартный текст библиотеки не должен становиться ответом команды. Основание: [clap Parser](https://docs.rs/clap/latest/clap/trait.Parser.html).

### C и файловая система остаются частью решения

Rust-библиотека rusqlite — безопасная обвязка вокруг C SQLite. Нативный vec1 тоже написан на C. Безопасность ownership не устраняет ошибки внутри этих библиотек, несовместимость ABI или требования к сборке. В этой пробе использован стандартный Unix VFS SQLite с F_FULLFSYNC и отдельной синхронизацией каталога; однако потеря питания не моделировалась. Исходник: [libsqlite3-sys SQLite 3.53.2](https://github.com/rusqlite/rusqlite/blob/v0.40.2/libsqlite3-sys/sqlite3/sqlite3.c).

Linux и macOS требуют собственных сборок. При статической поставке нужно отдельно учитывать libc, платформенные библиотеки и embedding runtime. Rust не убирает эти вопросы из дизайна.

## Сравнение для решения о языке

| Критерий | Go с нативным SQLite/vec1 | Rust с rusqlite/vec1 |
|---|---|---|
| Поиск SQLite/vec1 | Выполняется в C; локальная проба 12–17 мс | Выполняется в C; локальная проба 12–17 мс |
| Жизнь памяти приложения | GC и явные лимиты буферов/работников | Ownership, RAII и те же необходимые лимиты |
| Управление конкурентной работой | Goroutines, context, адаптация отмены в драйвере | Потоки либо async, явная передача отмены SQLite |
| Проверка владения ресурсами | Больше требований к дисциплине и проверкам | Больше ограничений проверяется компилятором; C и файловые гарантии остаются отдельными |
| Сложность для команды с опытом Go | Обычно ниже | Зависит от опыта Rust и готовности проектировать ownership |
| Минимальная исследованная обвязка | mattn + FTS5 + vec1 | rusqlite bundled/load_extension + vec1 |

Решение: выбран Rust с rusqlite и нативным vec1. Сравнение Go сохраняется для понимания компромиссов. Проверенный векторный поиск не даёт основания обещать многократное ускорение от выбора языка; контроль памяти, физическая схема, embedding-адаптер и нагрузка требуют отдельных проверок.

Исследовательские исходники, Cargo.lock и результаты находятся в [research/rust-sqlite](R-2-rust-sqlite/README.md). Язык и библиотеки уже выбраны; дальнейший дизайн уточняет физические схемы SQLite, режим vec1 и embedding-адаптер. Окончательную производительность определит весь путь поиска.
