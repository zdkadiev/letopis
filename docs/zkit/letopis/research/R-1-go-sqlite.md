# Engram 2.0 — Go, SQLite и векторные расширения

Дата проверки: 12 октября 2026 года. По итогам сравнения пользователь выбрал Rust, rusqlite и нативный vec1 для реализации Engram 2.0. Это Go-исследование сохраняется как анализ альтернатив и источник результатов временных проб. Для рассматриваемого здесь Go-варианта рекомендован `mattn/go-sqlite3` с нативным `vec1 0.8` и FTS5; этот драйвер не выбран для продукта. SQLite, WAL + FULL, fullfsync на macOS и FTS5 contentless-delete сохраняются. Выбранный стек рассмотрен в [Rust-сравнении](R-2-rust-sqlite.md).

Нативный вариант позволяет закрепить исходный код расширения независимо от Go-драйвера и использовать NEON/AVX2. Альтернатива без CGO — `ncruces/go-sqlite3` со встроенными Go-версиями расширений — тоже прошла основные проверки и упрощает сборку одного исполняемого файла. `modernc.org/sqlite` имеет готовую интеграцию другого расширения, sqlite-vec; это не замена vec1 с тем же SQL-контрактом.

Основание требований: [модель хранения](../mechanics/storage-model.md). Исследование охватывает библиотеки, регистрацию расширений, транзакции, фильтры, отмену и сборку. Продуктовый прототип Engram, получение embeddings и аварийный протокол Markdown/Git здесь не реализованы.

## Сравнение проверенных библиотек

| Библиотека | Проверенная версия | Подключение векторов | Практическое ограничение |
|---|---|---|---|
| `github.com/mattn/go-sqlite3` | `v1.14.52`, SQLite `3.53.4` | Нативный vec1 через `SQLiteDriver.ConnectHook` и `SQLiteConn.LoadExtension` | CGO и C-компилятор при сборке; расширение нужно поставлять для каждой ОС и архитектуры |
| `github.com/ncruces/go-sqlite3` | `v0.35.4`, SQLite `3.53.4` | `ext/vec1.Register`; FTS5 отдельно через `ext/fts5.Register` | В этой поставке vec1 `0.7`, Scalar, single-threaded; версия расширения зависит от модуля wasm |
| `modernc.org/sqlite` | `v1.58.0`, SQLite `3.53.4` | Импорт `modernc.org/sqlite/vec` регистрирует sqlite-vec `0.1.9` | Использует vec0 и другой синтаксис; нативный vec1 не подключается этим импортом |

Механизмы регистрации подтверждены исходным кодом и запуском: [mattn LoadExtension](https://github.com/mattn/go-sqlite3/blob/v1.14.52/sqlite3_load_extension.go), [ncruces vec1](https://github.com/ncruces/go-sqlite3/blob/v0.35.4/ext/vec1/vec1.go), [ncruces FTS5](https://github.com/ncruces/go-sqlite3/blob/v0.35.4/ext/fts5/fts5.go), [modernc vec](https://pkg.go.dev/modernc.org/sqlite/vec).

Актуальный ncruces использует wasm2go: скомпилированный WebAssembly переведён в Go. Это не загрузка `.so`/`.dylib` и не прежняя схема с wazero. Для имеющихся расширений есть готовые пакеты; добавление собственного C-расширения потребует его отдельной трансляции. Основание: [репозиторий драйвера](https://github.com/ncruces/go-sqlite3) и [поддерживаемые модули расширений](https://github.com/ncruces/go-sqlite3-wasm).

Настроенный Go-прокси отказал в загрузке `ncruces v0.35.6` из-за ограничения на пакеты моложе 30 дней. Проверка выполнена на доступной `v0.35.4`, с зависимостью `go-sqlite3-wasm/v5 v5.0.35304`. Выводы об исполняемом коде относятся к этим закреплённым версиям; автоматически переносить их на новый релиз нельзя.

Минимальные версии Go из проверенных go.mod: mattn — 1.21, ncruces — 1.26, modernc — 1.25. Самостоятельная исследовательская программа собиралась Go 1.27.1; версия Go для продукта этим не выбирается.

## Как подключать нативное расширение

Драйвер включается в Go-приложение, а vec1 собирается из закреплённого `vec1.c`. На macOS получается `.dylib`, на Linux — `.so`. Для проверенного исходника entry point — `sqlite3_extension_init`. Подключение через callback обязательно для каждого нового соединения пула. Основание: [SQLite loadable extensions](https://www.sqlite.org/loadext.html).

Пример инициализации драйвера, соответствующий выполненной проверке:

```go
sql.Register("engram-sqlite", &sqlite3.SQLiteDriver{
    ConnectHook: func(c *sqlite3.SQLiteConn) error {
        if err := c.LoadExtension(extensionPath, "sqlite3_extension_init"); err != nil {
            return err
        }
        _, err := c.Exec("PRAGMA fullfsync=ON", nil)
        return err
    },
})
```

Импорт `sqlite3` здесь означает `github.com/mattn/go-sqlite3`; `extensionPath` — путь к поставляемому расширению приложения. Инициализация выполняется один раз на процесс. DSN задаёт `_journal_mode=WAL`, `_synchronous=FULL`, `_busy_timeout` и `_foreign_keys=on`. В пробе все настройки прочитаны обратно на двух одновременно открытых соединениях. Таймаут ожидания блокировки в пробе не является новым согласованным параметром Engram.

Сборка драйвера требует `CGO_ENABLED=1` и тега `sqlite_fts5`. Без этого тега FTS5 в стандартной сборке mattn не включён. Тег `libsqlite3` переключает на системную библиотеку, поэтому её версию пришлось бы контролировать отдельно; для прототипа рекомендуется встроенная SQLite из закреплённого драйвера. Основания: [mattn](https://pkg.go.dev/github.com/mattn/go-sqlite3) и [реализация тега FTS5](https://github.com/mattn/go-sqlite3/blob/v1.14.52/sqlite3_opt_fts5.go).

В проверке исходник vec1 собран с `-O3 -DNDEBUG`, с согласованными SQLite-заголовками. Смешивание системного `sqlite3.h` и `sqlite3ext.h` из mattn привело к ошибкам повторного определения типов. Исправление — использовать один согласованный набор заголовков. На ARM64 сборка использует NEON; на x86 требуется учитывать доступность AVX2/FMA, иначе бинарник может не запускаться на старых процессорах. Официальная конфигурация поддерживает сборку с выбором подходящего варианта. Основание: [сборка vec1](https://www.sqlite.org/vec1.html).

LoadExtension в проверенной mattn включает загрузку на время регистрации и затем отключает её. Для поставки нужно выбрать загрузку заранее собранной библиотеки либо статическое включение C-кода. Второе позволяет получить один бинарник, но требует небольшой собственной CGO-интеграции; она здесь не проверялась. Окончательный способ поставки пока не выбран.

## Подключение без CGO

Проверенный ncruces открывается через callback, который регистрирует оба расширения:

```go
db, err := driver.Open(dsn, func(c *sqlite3.Conn) error {
    if err := fts5.Register(c); err != nil {
        return err
    }
    return vec1.Register(c)
})
```

Пакеты: `github.com/ncruces/go-sqlite3`, его `driver`, `ext/fts5` и `ext/vec1`. Первоначальная проба без регистрации FTS5 получила `no such module: fts5`; после регистрации прошла contentless-delete. Не следует считать, что поддержка FTS5 автоматически включена в любом SQLite-драйвере. Callback выполняется для новых соединений; параметры можно передать повторяемыми `_pragma` в DSN. Основание: [driver.Open](https://pkg.go.dev/github.com/ncruces/go-sqlite3/driver).

У modernc минимальное подключение sqlite-vec — импорты для побочного эффекта:

```go
import (
    _ "modernc.org/sqlite"
    _ "modernc.org/sqlite/vec"
)
```

Используется драйвер `sqlite`, таблица `vec0(embedding float[...])` и запрос с `embedding MATCH ... AND k=... ORDER BY distance`. Совместимость этого базового пути проверена на двух соединениях. Учитывая уже рассматриваемый vec1, перевод Engram на sqlite-vec потребовал бы отдельного сравнения поведения и поиска; окончательный дизайн нельзя строить на взаимозаменяемости этих расширений.

## Результаты локальной проверки

Среда: Go `1.27.1`, macOS ARM64, Apple clang `21.0.0`. Использовались временные файлы в `/private/tmp`; реальный корпус знаний не изменялся. Системная информация о модели ноутбука и объёме RAM была недоступна в sandbox, поэтому это не испытание требования о ноутбуке с 4 ГБ.

Проверены два vec1-варианта с SQLite `3.53.4`. Во всех соединениях прочитаны WAL, synchronous=2 (FULL), fullfsync=1 и foreign_keys=1. Выполнены:

- FTS5 contentless-delete: поиск находит rowid, текстовая колонка возвращает NULL, DELETE удаляет совпадение.
- Регистрация vec1 на двух одновременно открытых соединениях и повторная регистрация после закрытия соединений пула.
- Точный поиск flat/cos, UPDATE с последующим ROLLBACK и DELETE.
- Писатель меняет вектор при активной read-only транзакции: прежний читатель видит старый вектор и старый результат поиска, новое чтение — новый результат.
- Фильтрация с K=1 и streaming, описанная ниже.
- Отмена обычного SQL, векторного поиска и rebuild; последующий запрос работает, после отменённой перестройки число векторов сохранено и поиск доступен.

В пробе modernc отдельно прошли SQLite/vec_version, FTS5 contentless и базовый vec0-поиск на двух соединениях. Полная матрица vec1-проверок к нему не применялась.

Для измерения поиска сгенерированы 50 000 псевдослучайных векторов float32, 384 измерения, фиксированное зерно. Пять запросов возвращали по 10 результатов; первый запрос после перестройки включён в диапазон.

| Метрика финального запуска | mattn + нативный vec1 0.8 | ncruces + vec1 0.7 |
|---|---:|---:|
| Возможности из `vec1_info()` | NEON, multi-threaded | Scalar, single-threaded |
| Вставка 50 000 векторов | 430 мс | 599 мс |
| Перестройка flat/cos | 423 мс | 559 мс |
| Пять поисков, диапазон времени | 11,8–16,6 мс | 27,3–29,5 мс |
| Отмена поиска при контексте 1 мс | 1,18 мс | 8,59 мс |
| Отмена rebuild при контексте 1 мс | 1,16 мс | 1,35 мс |

Это проверка работоспособности и начальный замер, а не сравнительный benchmark драйверов: версии расширения и SIMD различаются, статистики p95/p99 нет. В время поиска не включены embedding запроса, FTS5, графовые фильтры, ранжирование гибридной выдачи и нагрузка десяти агентов. Автоматическое ограничение поисковых запросов по времени не предлагается; короткие deadline использованы только для проверки отмены.

Прямой объём float32-векторов составляет `50 000 × 384 × 4 = 76 800 000` байт. Файлы проб после закрытия имели примерно 98 МиБ после вставки и перестройки flat, с учётом структур SQLite и выделенных страниц этой версии. Это не прогноз полного размера БД Engram. Getrusage сообщил пиковый RSS около 19–22 МиБ для этих запусков, но такой замер не учитывает весь бюджет ОС, файлового кэша и embedding-модели; использовать его как подтверждение требования 4 ГБ нельзя.

Ncruces-проба также успешно собрана с `CGO_ENABLED=0` для Linux amd64 и arm64. Linux-бинарники не запускались; нативная Linux-сборка и macOS amd64 здесь не проверены.

## Подводные камни для дизайна Engram

### Фильтры должны действовать до окончательного лимита

В маленькой проверке ближайшая вершина не проходила фильтр, а вторая проходила. Следующий запрос с `K=1` вернул 0 строк; с `streaming=1` вернул 1:

```sql
SELECT vv.rowid
FROM v(:embedding, '{"K":1,"streaming":1}') AS vv
JOIN nodes n ON n.id = vv.rowid
WHERE n.selected = 1
LIMIT 1;
```

Здесь `nodes(id, selected)` — только схема исследовательской пробы. Предварительная выдача K кандидатов с последующим фильтром может потерять подходящие знания. Для внешних таблиц vec1 предлагает streaming; встроенные metadata-фильтры имеют ограничения по форме SQL. Для будущих фильтров Engram нужно проверить итоговые запросы, устранить дубли при множественных типах/источниках и применять лимит к различным результатам. Основание: [filtered vector queries](https://www.sqlite.org/vec1doc.html).

### Версия расширения и версия модели являются отдельными данными

`sqlite_version()` проверяет движок, `vec1_info()` — расширение. Версия Go-модуля не заменяет эти проверки. У vec1 все векторы таблицы имеют одну размерность, хранятся как float32 BLOB в порядке байтов машины; значения должны быть конечными. Векторный адаптер должен проверять размерность и числовую корректность. Поддерживаемые здесь macOS/Linux amd64/arm64 имеют little-endian; перенос на иной порядок байтов нельзя считать прозрачным. Основание: [формат vec1](https://www.sqlite.org/vec1ref.html).

Совпадение размерности не означает совместимости моделей. Смена модели или влияющих параметров требует согласованного переиндексирования; сравнивать вектор нового запроса со старой моделью нельзя. Это следует из принятого правила повторного использования embeddings, а не требует нового CLI-параметра.

### Пул соединений не равен одному SQLite handle

`sql.DB` — пул. Однократная загрузка расширения или PRAGMA через `db.Exec` не гарантирует настройку следующих соединений. Регистрация и параметры соединения задаются при открытии, затем проверяются. Все операции одной транзакции выполняются через её `sql.Tx`. Пул и ожидание SQLite-блокировок должны учитывать отмену. В пробах mattn возвращал `context deadline exceeded`, ncruces — `sqlite3: interrupted`; прикладной слой должен сопоставлять их с согласованной ошибкой отмены.

### WAL оставляет одного писателя

Embeddings вычисляются вне транзакции записи. Подготовка новой поисковой структуры через vec1 всё равно выполняет SQLite-записи и может задержать короткие служебные транзакции. Физический дизайн должен предусмотреть ограниченные порции подготовки и короткую финальную публикацию после готовности всех индексов. Длительные read-транзакции удерживают WAL и могут мешать checkpoint; это особенно важно для десяти агентов и ограниченной памяти. Основание: [WAL concurrency и checkpoint](https://www.sqlite.org/wal.html).

Проверенная изоляция чтения векторов полезна, но сама не обеспечивает одновременную публикацию графа, FTS5 и embeddings. Они должны относиться к одной опубликованной версии по принятому протоколу. Перестройка должна сохранять предыдущую доступную версию при ошибке, как уже согласовано.

### FULL и fullfsync не доказывают весь аварийный протокол

В ncruces проверено наличие вызова `F_FULLFSYNC` в стандартном macOS VFS. Если он не поддержан, код использует `fsync`. Основание: [os_darwin.go v0.35.4](https://github.com/ncruces/go-sqlite3/blob/v0.35.4/vfs/os_darwin.go).

Есть отдельное наблюдение по исходнику этой версии: в `vfsFile.Sync` при `_FLAG_SYNC_DIR` открывается родительский каталог `d`, но повторный `osSync` вызывается для `f.File`. Это потенциальный дефект синхронизации каталога, который требует разбора перед выбором этого драйвера для нашего протокола потери питания. Вывод о последствиях не подтверждён аварийным экспериментом. Основание: [file.go v0.35.4](https://github.com/ncruces/go-sqlite3/blob/v0.35.4/vfs/file.go).

Проба не выключала компьютер и не проверяла сохранность Git-объектов, refs, Markdown-файлов или БД после потери питания. SQLite WAL защищает её данные; прежняя прикладная запись восстановления и долговечное сохранение файлов остаются необходимыми. Согласованный порог SQLite 3.51.3+ и настройки FULL проверяются на конкретном поставляемом бинарнике, а не по версии системного sqlite3.

### Flat и ANN требуют разных проверок

Flat — полный поиск; стоимость растёт с количеством и размерностью векторов. Число документов не равно числу индексируемых фрагментов. Одна секунда на 50 000 векторов без модели запроса не подтверждает полный поиск Engram на десятках тысяч документов. При переходе на ANN нужно измерять полноту относительно точного flat и определить обучение/перестройку; для сжатых ANN-векторов vec1 обычно требует reranking. Основание: [руководство vec1](https://www.sqlite.org/vec1doc.html).

Отмена core-SQL и flat прошла в этой пробе, но этого недостаточно для гарантии своевременной отмены длительного ANN-обучения. Оно должно проверяться отдельно вместе с прогрессом, ошибками расширения и восстановлением задания.

## Что ещё проверить перед окончательным выбором

1. Реальный корпус, максимальную размерность и десять параллельных агентов, с полной цепочкой гибридного поиска и локальной моделью в пределах целевого оборудования.
2. Linux amd64/arm64 и macOS amd64/arm64, конкретную C-сборку, версии и возможность запуска на процессорах без AVX2.
3. Аварийные сценарии SQLite/Markdown/Git и совместную публикацию, включая повреждения, заполнение диска и сбой в каждой фазе записи.
4. Окончательные rowid/UUID, схему векторов, отфильтрованную выдачу, checkpoint и размер WAL при долгих читателях.

Эти проверки определяют готовность реализации. Рекомендация mattn + нативный vec1 обусловлена прямой интеграцией официального C-расширения, доступностью SIMD и выявленным вопросом к VFS альтернативы. Она сохраняет одну SQLite-БД, прежний embedding-порт и все CLI-контракты; новых продуктовых команд или параметров не вводится.
