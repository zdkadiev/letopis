# Проверка итерации contracts после R1

Дата начала итерации: 2026-10-18. Навык: zkit:contracts 0.2.3 (6065d8a). Область: спецификация, не реализация Engram. Новые замеры, вызовы inference, создание Git-коммитов и нагрузочные эксперименты не выполнялись.

## Итог интервью
R1 закрыт: **2/2 в раунде**, **7 принятых решений текущего интервью** с учётом D-65…D-69, **0 в очереди**. G1 — FTS/граф/запись до настройки модели, config:null (D-70). G2 — reindex ждёт graph/FTS и постановку заданий, а не вычисление векторов (D-71). Нового раунда не требуется по результатам текущей сверки.

## Проверки
- Машиночитаемые артефакты: CLI JSON Schema с 12 командами/режимами, OpenAPI используемого подмножества двух provider-протоколов, JSON Schema Markdown-метаданных с отдельной грамматикой в карточке X-4.
- CLI examples: 60, provider examples: 6, metadata examples: 8. Всего 90 проверок утверждений о форме/ограничениях, ошибок нет. Есть негативные примеры для отсутствующих хешей/строк, неизвестных полей, uppercase/trailing-newline ID, недопустимого временного имени и secret в parameters.
- Проверены соответствие индексов/числа/размерности векторов входам на синтетических примерах. Это проверка указанного инварианта, не тест реально реализованного адаптера.
- check_contracts.py: exit 0, 4 границы, 0 unverified consumed contracts в проверяемом документированном подмножестве, 0 open forks. Статус verified относится к протоколу/документации, не к работе приложения и не к произвольному стороннему совместимому серверу.
- check_requirements.py: exit 0; остаётся прежнее объяснённое предупреждение о 95% Must. Требования и ресурсные числа не изменены.
- PyYAML/jsonschema установлены только во временное виртуальное окружение; версии сохранены в [contracts-checks.json](contracts-checks.json). Схемы дополнительно проверены [check_contract_examples.py](check_contract_examples.py): основной checker читает четыре карточки, а этот скрипт явно валидирует вложенные схемы и примеры.
- Linker выполнен на подготовленной копии. Исходные concept/requirements/resource-math сохранены байт-в-байт. Готовность артефакта проверяется отдельно от сохранности bytes источников.

| Canonical UUID допускали uppercase | Принятые строчные UUIDv4 зафиксированы в CLI/метаданных/title | подтверждено reviewer и негативными примерами |

Contracts остаётся **draft**: resource-math — draft/not assessed, runtime/crash/конкурентные гарантии требуют реализации и прежних P-2/P-3. Они не названы дополнительными согласованными требованиями. Схемы/примеры не заменяют application-проверки целостности, диапазонов и файлов.
