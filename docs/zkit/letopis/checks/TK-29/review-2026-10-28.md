## Findings and corrections

1. **Repeated signals were not exercised.** The former
   `repeated_sigint_keeps_one_response` only called ResponseWriter repeatedly.
   Its accurate writer-idempotence coverage remains under a clearer name. A new
   owned-child test sends three actual SIGINTs: after the first, the real callback
   is held inside its first output write while it owns the response guard. The
   parent delivers two more signals, releases the write, and asserts the exact
   cancelled envelope and exit 1.
2. **Backpressure readiness was inferred from timing.** Five unchanged FIONREAD
   samples could also describe a descheduled or completed producer. The fixture
   now publishes readiness only after a real nonblocking socket write returns
   WouldBlock. Blocking mode is restored before the checkpoint, and the same
   response guard covers the remaining write and flush. This proves an incomplete
   write under pressure; it does not claim that the signal arrives at a specific
   machine instruction inside the subsequent blocking syscall.
3. **Small AGENTS.md violations.** Corrected caller-before-helper ordering,
   grouping of the public composition API, encoder/write API documentation,
   explicit type imports, verb-based workflow/helper names, private child test
   phases, and Debug/documentation on new shared fixtures. Removed a private
   cleanup forwarding helper with only one caller.

The response tests are now split between writer-unit tests and owned-process
signal proofs. Native wait observations are separate from owned Git/process
fixtures. Each new helper file has one responsibility and stays below 500 lines;
new/touched function bodies stay below 60 lines. Existing unrelated modules and
large pre-existing composition APIs were not mechanically restructured.

No production behavioral defect was found. Product Rust edits in this review
change ordering, imports and documentation only; signal ownership, config
validation, storage transactions and application behavior are preserved.

## Architectural review

- Domain remains independent of signals, output and infrastructure.
- ConfigurationService uses the application-owned ConfigReader, StatusFiles and
  EmbeddingProvider interfaces and never invokes readiness or inference.
- CLI handlers invoke service interfaces. ResponseWriter owns encoding/output
  arbitration and holds its guard through write plus flush.
- SigintListener owns registration, its ordinary thread and process termination.
  It is installed only by the executable composition path for the five commands.
- lib.rs constructs the collaborators; main.rs remains a thin entry point.
- No async runtime, extra dependency, persistent state, speculative abstraction
  or changed storage/native input was added.
