## Findings and corrections

- **Final revision mismatch:** readiness accepted a `product.final_base` different
  from the commit used for seeds and their base recheck. Require the same full OID;
  a new final product revision requires fresh preparation and recheck.
- **Usage double-counting:** a real correlation ID `uncorrelated-1` collided with
  the generated ID of a request lacking correlation. Both rows received one
  completion's counters and `complete=true`. Generate collision-free unknown rows
  without completion lookup; missing usage remains null/incomplete.
- **Evaluator lifecycle:** subprocess timeout terminated only the command leader;
  a child could modify state after the final audit. Own a process group and kill
  its remaining members on completion, timeout and interruption. Deliberately
  escaped sessions still require external containment.
- **Manual verdict integrity:** annotations were outside the operator-state guard.
  Include their creation, modification and deletion, plus all tooling sources;
  ignore only generated `__pycache__`. Malformed annotations yield unknown verdicts,
  and check values must be actual booleans or null, never numeric substitutes.
- **Oracle omissions:** general help omitted `embed --drain`; installed-workflow
  scoring accepted command names without observing request/results; C3's late-result
  scenarios omitted document removal. Add independent observations and negative
  controls for those requirements, without implementing the participant features.
  Cross-review also corrected false rejection of `.markdown` fixtures and missing
  `check → search → inspect → reindex` sequence validation; repeated verification
  calls remain allowed.
- **Invalid preparation inputs:** non-object JSON could escape as a traceback;
  unchecked chain/task IDs could mismatch condition layout and oracle dispatch.
  Validate these boundaries before reporting readiness or preparing directories.
