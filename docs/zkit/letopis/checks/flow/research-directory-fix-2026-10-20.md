# Исправление обхода research/ в штатных checker-ах zkit

Дата: 2026-10-20. Область: requirements/architecture scripts zkit и повторный прямой запуск проверок Letopis. Исправление локально внесено в `/Users/zdkadiev/Repos/zkit` и установленный пакет `zkit@personal` 0.2.6. Версия не переименована в новый релиз; commit/push и публикация не выполнялись.

## Причина и исправление

Оба checker-а получали все имена из `os.listdir(research)`. Каталог с артефактами отчёта попадал и в проверку наличия отчёта, и в цикл чтения. При чтении происходил `IsADirectoryError`; каталог также мог ошибочно удовлетворить проверке существования цитируемого отчёта.

В обоих scripts отбор выполняется до проверки ссылок: только обычные файлы с именем `R-n-*.md`. Каталоги, включая каталог с суффиксом `.md`, README и бинарные метаданные пропускаются. Само чтение настоящих отчётов и диагностика ошибок документов сохранены. Новая общая библиотека, зависимость или формат данных не вводились.

Изменённые файлы репозитория zkit:

- `skills/requirements/scripts/check_requirements.py`;
- `skills/architecture/scripts/check_architecture.py`;
- `tests/test_research_reports.py` — самостоятельные stdlib unittest fixtures.

## Регрессия

На исходном коде четыре теста запускались до исправления: два положительных подслучая без каталогов проходили, шесть подслучаев воспроизводили исходный сбой. После исправления полная существующая unittest suite проходит: **4 теста, 8 подслучаев**.

Проверяются:

1. Настоящий отчёт обрабатывается рядом с каталогами артефактов, README и бинарными данными; наблюдаемая диагностика подтверждает чтение отчёта.
2. Каталог с именем отчёта не подменяет отсутствующий файл и вызывает штатную ошибку ссылки, без traceback.
3. Цитируемый существующий отчёт находится.
4. Дубликаты ID в реальных документах по-прежнему отклоняются.

Запуск из `/Users/zdkadiev/Repos/zkit`: `python3 -B -m unittest discover -s tests -v`.
