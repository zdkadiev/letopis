После host проза README изменилась; текущая `tests/cli/tk24_workflow.py` также изменена как исполняемый helper, а не документация. `.artifacts/tk24/workflow-fix1/input-map-delta.json` (SHA-256 `4247f2ee31b52d0683162d2b1ad3aa3497b87adffb48df99679fa2cc0043255d`) сравнивает все 205 inputs: только README (`a06764...` → `062fd7...`) и helper (`e9b76...` → `79f070...`) отличаются; остальные **203 byte-identical**, включая product/runner. Поэтому прежний host PASS не выдается за повторный полный run текущего helper; helper независимо выполнен заново, Python collector 20/20. Это следует правилу AGENTS.md не повторять неизменённый полный product suite ради изолированного harness/refactor.

Не запускались Linux CLI runner, native storage runner (storage/native/build inputs не менялись), исторические proof harnesses, реальный provider/модель/пилот, resource G-1/G-2, handled SIGINT и будущие TK-25–29/TK-44. Search/traverse используют собственный SQLite read view; обычные live file reads могут пересечь правку между файлами. Inspect tree сохраняет захваченные bytes, но capture рабочей копии не является атомарным межфайловым снимком. Review и release-решение остаются отдельными действиями.
