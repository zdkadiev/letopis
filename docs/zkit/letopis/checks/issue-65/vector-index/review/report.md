## Findings fixed during review

**Important, resolved: catalog model normalization hid a corrupt distance tag.**
The initial classifier trusted `vec1cat.model`. Native `vec1.c:12692` renders
every distance value except L2 as "cos", while distance execution selects cosine
only for the exact COS tag (`8418`, `9131`). Native DecodeModel does not reject
an unknown distance field. Thus a corrupt tag 3 could be accepted as none/cos
and silently replaced with genuine cosine during migration. The worker added
a concrete regression, whose saved RED fails at the expected bootstrap-error
assertion, then fixed the classifier. Final `vector_index.rs:53-84` compares the
opaque stored model against flat/cos and none/cos models generated by the same
pinned module in a separate in-memory database. Unknown/model/metric variants
are safely rejected, with no private binary-header decoder or persistent cache.
The production catalog/JSON classification layer was removed altogether.

**Important, resolved: conversion could recreate corrupt native model-version state.**
A legacy none model with missing native config MODEL row could pass raw-model and
dimension checks, then native rebuild would recreate its version metadata. Native
configuration loading permits absence of that row, so model-byte identity alone
does not establish this conversion precondition. Final `vector_index.rs:88-100`
requires an i64 version strictly greater than zero and below i64::MAX before any
legacy native query/rebuild. Missing/incorrectly typed/nonpositive values and
increment overflow cannot be repaired by conversion. The saved regression has
a genuine RED for deleted id0 and a final GREEN covering five concrete invalid
states. This is a narrow conversion guard, not a general vec1 corruption audit;
already-flat data keeps its baseline observation/error behavior.

**Minor, resolved: initial model inspection had no contention retry.**
The first added read transaction now uses the existing bounded contention helper
(`vector_index.rs:18-23`), matching schema readiness behavior. The immediate
conversion attempt already used the same bounded retry policy.

**Minor, resolved: schema.rs grew far beyond the file-size guideline.**
The coherent physical-mode protocol and its new inline tests were moved into the
private 481-line storage/vector_index.rs. schema.rs now only imports and invokes
the operation after ordinary structural bootstrap; VectorStorage and its trait
implementations remain in vector.rs. Newly sibling-visible fallible functions
have their required error documentation.

## Migration, error and resource review

Fresh DDL and configuration-reset DDL both select exact flat/cos. Structural
schema version remains 1, because table/public contracts do not change. Existing
recognized none databases are handled explicitly; this is not a DDL-only change.
The bootstrap call remains before consumer vector attachments/read scopes in
lib.rs, and observational status validation does not invoke this migration.

Preparation first pins a completed read transaction and classifies the exact
opaque model. Already-flat, query-only and actual read-only connections return
without requesting a writer or rebuilding the target database. Factory generation
writes only a separate ephemeral reference. No global mode/model cache or new
application configuration is introduced. Query-only legacy none/cos stays none.

For writable legacy none, `vector_index.rs:30-48` acquires an immediate transaction
and reclassifies after contention. A competing opener that already published flat
is accepted without a redundant rebuild. The conversion guard then checks model
version and validated native dimension state and streams every stored native row.
Each row must be a blob of the exact stored width before the existing finite-value
decoder runs (`101-120`). No corpus-sized Vec or raw payload cache is created;
the decode allocation is bounded by the accepted native dimension range, and each
temporary is dropped before the next row. Missing dimensions are valid only when
there are no rows. Valid retained dimensions survive the empty-after-delete case.

Only then does the native rebuild execute. It does not delete/recreate the index
or clear keys, identity, failure attempts, query_error, or dimensions. Flat idx
blocks contain authoritative vector bytes; this implementation respects that
ownership and does not treat them as disposable secondary data. Original rowids,
f32 bytes (including signed zero), application state and dimensions are preserved
by the native path and independently exercised by the new state test.

Every inspection/row cursor is local to its helper and dropped before rebuilding,
commit/rollback, or retry. Transaction failure uses the existing RAII rollback
pattern; native xRollback unloads the model and discards its writer. The injected
failure test specifically reaches failure after the new model was written, then
checks transaction closure, old mode/state and same-handle plus reopen retry.
Separate-connection pinned-reader coverage retains the old none representation
across writer publication and observes flat only after ending that read view.
No public source/provenance/current-byte observation order or error contract is
changed by the physical mode preparation.
