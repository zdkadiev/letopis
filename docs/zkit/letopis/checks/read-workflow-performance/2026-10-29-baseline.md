## Method

Requests were run serially. A Python supervisor sent JSON, retained response/stderr files, timed each complete call, and asserted exit 0 plus `ok:true`. Two seconds after starting each of the first three commands, `/usr/bin/sample <pid> 5 -file <new-file>` collected symbolized Rust stacks. Instruments `xctrace` is unavailable on this host. No profiler was attached to the separately counted run.

The counted search prepended an owned shell wrapper directory to PATH. The wrapper appended Git argv to a private file and then used `exec` to launch the original `/usr/bin/git`. It did not modify product code, requests, Git inputs, Markdown or configuration. Wrapper launch/logging increases latency; its time is not interchangeable with the unwrapped samples. Resource totals in the manifest include profiler child work and must not be reported as isolated product CPU time.

Raw evidence is local and ignored: [manifest](../../../../../.artifacts/read-profile-20261029-131127/manifest.json), [supervisor](../../../../../.artifacts/read-profile-20261029-131127/profile.py), [search sample](../../../../../.artifacts/read-profile-20261029-131127/search.sample.txt), [traversal sample](../../../../../.artifacts/read-profile-20261029-131127/traverse.sample.txt), [inspection sample](../../../../../.artifacts/read-profile-20261029-131127/inspect.sample.txt), and [counted Git argv](../../../../../.artifacts/read-profile-20261029-131127/git-invocations.txt). ## Integrity and consistency audit

The existing `GitSnapshots::pin` contract explicitly validates the complete local closure. Tests corrupt or delete descendants after a successful pin and require subsequent pins to fail. Existing refs therefore cannot safely become a verification bypass without changing that guarantee.

Publication retains author bases under index.lock before opening a SQL write unit. Failure prevents publication; byte/stat checks guard later capture, and SQLite commit publishes one revision. Batching must preserve this sequence, exact ref/CAS rules, no-alternates/no-lazy-fetch policy and safe typed diagnostics.

Focused current-tree validation passed before design drafting:

```text
cargo test --locked --offline --test git_corruption --test git_retention
  3 corruption + 11 retention tests passed
cargo test --locked --offline --lib service::document_refresher::tests::basis
  7 tests passed
```

The independent Superpowers builder check raised two questions, now resolved in the spec: raw mode normalization must match Git rather than impose stricter canonical modes, and SIGINT must preserve the current process-exit architecture with real-child pipe-closure testing rather than depend on destructors.

## Limits and next measurements

These are single dev-build observations, not medians, optimized-build numbers or Linux measurements. Instrumentation has overhead. The later counted run observed a publication caused by newly written unmarked design documentation, so it is a subprocess diagnostic rather than a controlled before/after latency baseline. The initial search/traversal samples read revision 3 and cover the unchanged-retention path.

Before implementation, freeze the corpus and collect matched optimized-build baselines with symbols and three warmed runs per operation. Repeat those settings after implementation. Separate local FTS, provider inference, publication and inspect capture costs. Keep full corruption/publication regression coverage. No speedup has yet been implemented or measured.
