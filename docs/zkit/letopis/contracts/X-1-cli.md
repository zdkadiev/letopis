## Layout
Машиночитаемый каталог всех входов, успешных ответов и общей ошибки: [X-1-cli.yaml](schemas/X-1-cli.yaml), JSON Schema 2020-12. Поле x-commands сопоставляет имя команды с input/success/error внутри $defs. Имя команды и флаги находятся в argv, в stdin — только описанный JSON без новой обёртки command. Примеры: [contracts-examples.json](../checks/contracts/contracts-examples.json). Каталог — дизайн, не реализация CLI.

| Команда | Вход / успешный result | Семантика |
|---|---|---|
| check | необязательный paths / errors | проверка всего корпуса или путей по X-4; файлы не меняются; пустой errors — корпус валиден, [D-93](../decisions.md#D-93) |
| inspect | element_ids / snapshot, elements | актуальные path/lines/hash знаний и source одного Git-снимка, без текста; неизвестный ID отклоняет пакет |
| search | query, limit, необязательный filters / список ссылок | гибридный поиск; до настройки и при сбое query embedding — FTS |
| traverse | element_ids, mode, direction, depth, limit; необязательные edge_types, edge_limit / elements и опциональный edges | relations/containment/both; стартовые элементы исключены, повторные достижения возвращаются один раз |
| reindex | {} / revision | полная перестройка графа/FTS под index.lock; векторы не ожидаются, D-71, [D-95](../decisions.md#D-95) |
| status | {} / revision, embedding_backlog, embedding_failed, locks (занятые flock index/embed и PID), problems | только текущее состояние: число текстов без вектора и с исчерпанными попытками, текущие проблемы (невалидные файлы, висячие ссылки, циклы includes, отсутствующие в Git source_snapshot, исчерпанные попытки embeddings, последняя ошибка embedding запроса, невалидный config.json), [D-95](../decisions.md#D-95) |
| config | {} / конфигурация либо null | читает `.letopis/config.json`; до настройки (файла нет) result:null; меняется правкой файла, D-70, D-91, [D-95](../decisions.md#D-95) |
| embed --drain | {} / {} | внутренняя, не для агентов ([D-94](../decisions.md#D-94)): отсоединённый процесс под embed.lock вычисляет векторы текстов без вектора и завершается с exit 0, когда работы нет или блокировка занята |

Пути относительны Git-корню. ID знания — путь или путь#якорь (KnowledgeId), ID source — нормализованный адрес (SourceId: path или path#Lstart-Lend), [D-91](../decisions.md#D-91)/[D-93](../decisions.md#D-93); UUID нет. ElementId в inspect/traverse принимает обе формы; путь обозначает либо элемент корпуса, либо source. Рёбра возвращаются тройками source/target/type без ID. Source без текущих ссылок отсутствует в графе: его адрес даёт not_found. Файл `.letopis/config.json` имеет схему Configuration и правится агентом или пользователем как файл; его identity — SHA-256 канонического JSON (JCS), поэтому переформатирование файла не сбрасывает векторы, а смена содержимого сбрасывает `.letopis/vectors.db` при следующем вызове (сброс — одна транзакция записи vectors.db (BEGIN IMMEDIATE): повторная сверка identity, пересоздание vec1, очистка vector_keys и embed_failures, запись meta.config_identity; блокировки index.lock/embed.lock не берутся, drain перед сохранением вектора сверяет meta.config_identity и при несовпадении завершается); содержимое, не прошедшее эту схему, даёт существующую ошибку валидации конфигурации, поиск работает через FTS. Служебная БД — пересоздаваемый кэш; её удаление не меняет контракт команд, следующий вызов выполняет reindex, а векторы неизменных текстов из `.letopis/vectors.db` переиспользуются (D-92). SHA-256 представлен 64 строчными hex, snapshot — полный Git OID, revision — счётчик публикаций индекса (D-95); точный тип tree проверяется приложением. Источник ребра — элемент, содержащий ссылку.

## Timing and limits
Один JSON в stdout, без потоковых прогресс-сообщений; exit 0 для ok:true, 1 для ok:false, включая обработанную отмену. Ошибки имеют code/message/details. Status.problems перечисляет только текущие проблемы в том же формате Diagnostic; исправленная проблема исчезает без очистки, истории и lifecycle-флага нет ([D-95](../decisions.md#D-95)). Принудительное уничтожение процесса не обещает JSON-ответ. Числовые транспортные лимиты не добавляются; limit и edge_limit положительны, depth неотрицателен, пустые старты недопустимы. Фильтры и селекторы с пустыми списками эквивалентны отсутствующим, дубли обрабатываются один раз.

Каждый вызов search/traverse/inspect/check перед ответом обнаруживает изменённые файлы и публикует их валидные изменения в graph/FTS ([D-93](../decisions.md#D-93)). Reindex ждёт graph/FTS. Векторы не ожидаются. Первый search при отсутствии индекса дожидается graph/FTS. До конфигурации модели работа через FTS разрешена. Прогретая секунда — цель, не отсечка; search не обрезается по времени. SIGINT завершает свой процесс search/traverse/reindex, не чужие ([D-94](../decisions.md#D-94)); незавершённая перестройка не заменяет прежний кэш. Отмены чужого процесса нет ([D-95](../decisions.md#D-95)).

## Errors and retry
Каталог: invalid_request, not_found, validation_failed, embedding_failed, internal_error, cancelled; conflict исключён вместе с base_hash ([D-93](../decisions.md#D-93)). Все ошибки проходят общий JSON-формат. Ошибки разметки и целостности — validation_failed; отсутствующий запрошенный ID/допустимый Git OID — not_found. Неверный формат/тип snapshot — invalid_request. Подробные условия сохраняются в [контрактах](../contracts.md).

Команд записи корпуса нет: правки делает агент, check и индексация идемпотентны. Повтор reindex перестраивает граф/FTS заново; векторы неизменных текстов переиспользуются. В схеме x-idempotency у каждой команды указан явно.

При ошибке query embedding успешный FTS возвращает обычный search; последняя такая ошибка хранится одной строкой query_error в `.letopis/vectors.db` и видна в status.problems, пока следующий успешный embedding запроса её не удалит (D-62). Сбой запуска drain — предупреждение в необязательном поле warnings ответа любой команды; оно не сохраняется ([D-95](../decisions.md#D-95)). Ошибка фонового embedding не отменяет уже сохранённые документы и не меняет завершённый успех reindex. Публикации сериализуются flock на index.lock; читатели используют снимки SQLite. Текст документов/источников не возвращается через search/inspect/traverse; агент читает Git/Markdown самостоятельно.

## Runtime-проверки сверх JSON Schema
Приложение проверяет bytes/hash, доступность и тип объектов Git, границы строк end>=start, ссылки, уникальность якорей в файле, наличие created_at, includes DAG и принадлежность путей корню с учётом symlink. Schema не может доказать состояние файлов или аварийный протокол.

## Допущения до реализации
URI base_url включает API-префикс; его локальная проверка и построение запроса определены X-2. Состав status — по FR-32 и [D-95](../decisions.md#D-95), проверяется контрактными примерами. Алгоритм обхода, обнаружение изменений и блокировки — mechanics. Секреты не попадают в JSON или диагностику. Все приведённые примеры являются синтетическими примерами формы.

## Область согласованного чтения — 2026-10-19

Согласованное чтение нескольких документов выполняется по одному неизменяемому Git-снимку (существующий snapshot из inspect), [D-77](../decisions.md#D-77). Обычные чтения живых Markdown-файлов разрешены, но могут пересекать правки агентов и не получают межфайловой гарантии. Search/traverse сохраняют собственный согласованный снимок SQLite; он не распространяется автоматически на последующее чтение файлов. Протокол reader locks не вводится. CLI не возвращает содержимое документов; агент читает его самостоятельно. Состав JSON-ответов и перечень команд не меняются.

2026-10-19, [D-78](../decisions.md#D-78): max_retries обязателен в полном объекте конфигурации и его ответе; 0 означает только первую попытку, 3 — до четырёх попыток всего. Параметр не является частью HTTP-body провайдера. До настройки конфигурация остаётся null. Изменение любого поля, в том числе только этого, меняет identity и сбрасывает векторы и попытки ([D-95](../decisions.md#D-95)).
