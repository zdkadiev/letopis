## Layout
Машиночитаемый каталог всех входов, успешных ответов и общей ошибки: [X-1-cli.yaml](schemas/X-1-cli.yaml), JSON Schema 2020-12. Поле x-commands сопоставляет имя команды с input/success/error внутри $defs. Имя команды и флаги находятся в argv, в stdin — только описанный JSON без новой обёртки command. Примеры: [contracts-examples.json](../checks/contracts/contracts-examples.json). Каталог — дизайн, не реализация CLI.

| Команда | Вход / успешный result | Семантика |
|---|---|---|
| apply | operations, необязательный base_hashes / hash и ids только при новых ID | create/edit/delete размеченных фрагментов; порядок операций сохранён; финальная проверка всей группы |
| apply --check | тот же вход / paths, element_ids | без сохранения и резервирования ID |
| inspect | element_ids / snapshot, elements | актуальные метаданные одного Git-снимка, без текста; неизвестный ID отклоняет пакет |
| search | query, limit, необязательный filters / список ссылок | гибридный поиск; до настройки и при сбое query embedding — FTS |
| traverse | element_ids, mode, direction, depth, limit; необязательные edge_types, edge_limit / elements и опциональный edges | relations/containment/both; стартовые элементы исключены, повторные достижения возвращаются один раз |
| reindex | paths и/или element_ids, либо {} / revision | полная или выборочная проверка, публикация графа/FTS и постановка заданий; векторы не ожидаются, D-71 |
| reindex --cancel | {} / revision либо null | отмена активной перестройки; опубликованное не откатывается |
| status | {} / revision, reindex, embedding_jobs, locks, errors | completed — процент текущего этапа; очередь не включает failed |
| errors | {} / список диагностик | чтение не очищает |
| errors --clear | {} / оставшиеся диагностики | очищаются завершённые неуспешные правки, активные ошибки остаются |
| config | {} / конфигурация либо null | до настройки result:null, D-70 |
| config --set | provider, model, parameters, max_retries / {} | полная замена; локальная валидация; прежняя транзакция замены очереди и векторов, без ожидания вычислений |

Пути относительны Git-корню. ID — UUIDv4, временные имена tmp:000–tmp:fff только в создающей правке. SHA-256 представлен 64 строчными hex, snapshot/revision — полный Git OID; точный тип tree проверяется приложением. Hash правки вычисляется по исходному JCS до подстановки ID. Источник ребра — размеченный элемент, содержащий ссылку; рёбра отдельно не редактируются.

## Timing and limits
Один JSON в stdout, без потоковых прогресс-сообщений; exit 0 для ok:true, 1 для ok:false, включая обработанную отмену. Ошибки имеют code/message/details. Принудительное уничтожение процесса не обещает JSON-ответ. Числовые транспортные лимиты не добавляются; limit и edge_limit положительны, depth неотрицателен, пустые старты недопустимы. Фильтры и селекторы с пустыми списками эквивалентны отсутствующим, дубли обрабатываются один раз; operations не дедуплицируется. Для reindex пустые селекторы означают полный режим.

Apply синхронно фиксирует документы, graph/FTS, revision, служебное состояние и embedding_jobs. Reindex ждёт graph/FTS и постановку заданий. Оба не ждут векторы. Первый search при отсутствии индекса дожидается graph/FTS. До конфигурации модели работа через FTS разрешена. Прогретая секунда — цель, не отсечка; search не обрезается по времени. SIGINT отменяет свой search/traverse/reindex, не чужие независимые запросы.

## Errors and retry
Каталог: invalid_request, not_found, conflict, validation_failed, embedding_failed, internal_error, cancelled. Все ошибки проходят общий JSON-формат. Устаревший base_hash/base_hashes даёт conflict; ошибки разметки и целостности — validation_failed; отсутствующий запрошенный ID/допустимый Git OID — not_found. Неверный формат/тип snapshot — invalid_request. Подробные условия сохраняются в [контрактах](../contracts.md).

Apply не имеет бессрочной дедупликации по hash: после потери ответа агент сначала перечитывает состояние. Config --set также не обещает кэш результатов и специальную оптимизацию идентичных вызовов. Reindex присоединяется к подходящей работе того же снимка/области, но ждёт лишь публикацию и задания. Повтор reindex может заново поставить работу. В схеме x-idempotency у каждой команды указан явно.

При ошибке query embedding успешный FTS возвращает обычный search без дополнительного предупреждения; ошибка доступна в status. Ошибка фонового embedding не отменяет уже сохранённые документы и не меняет завершённый успех reindex. При восстановлении поиск и новые записи ждут согласованного состояния. Текст документов/источников не возвращается через search/inspect/traverse; агент читает Git/Markdown самостоятельно.

## Runtime-проверки сверх JSON Schema
Приложение проверяет bytes/hash, доступность и тип объектов Git, границы строк end>=start, ссылки, уникальность ID, неизменность created_at, includes DAG, текущие предпосылки, принадлежность путей корню с учётом symlink и многофайловую атомарность. Schema не может доказать состояние файлов или аварийный протокол.

## Допущения до реализации
URI base_url включает API-префикс; его локальная проверка и построение запроса определены X-2. Конкретные stage и completed:null при неизвестном проценте — редакторская формализация существующего status, проверяется контрактными примерами; новый статус или поле не добавляется. Алгоритм обхода и конкурентное сохранение — mechanics. Секреты не попадают в JSON или диагностику. Все приведённые примеры являются синтетическими примерами формы.

## Область согласованного чтения — 2026-10-19

Согласованное чтение нескольких документов выполняется по одному неизменяемому Git-снимку (существующий snapshot из inspect), [D-77](../decisions.md#D-77). Обычные чтения живых Markdown-файлов разрешены, но могут пересекать применение правки и не получают межфайловой гарантии. Search/traverse сохраняют собственный согласованный снимок SQLite; он не распространяется автоматически на последующее чтение файлов. Протокол reader locks не вводится; физическая замена файлов не выбирается как обязательный способ применения правки. CLI не возвращает содержимое документов; агент читает его самостоятельно. Состав JSON-ответов и перечень команд не меняются.

2026-10-19, [D-78](../decisions.md#D-78): max_retries обязателен в полном объекте конфигурации и его ответе; 0 означает только первую попытку, 3 — до четырёх попыток всего. Параметр не является частью HTTP-body провайдера. До настройки конфигурация остаётся null. Сохраняется прежняя полная транзакционная замена конфигурации/векторов/очереди, в том числе при изменении только этого поля; специальная оптимизация не добавляется.
