## Layout
Порт остаётся texts → vectors, одна активная конфигурация и модель для документов/запросов. [OpenAPI используемого подмножества](schemas/X-2-embeddings.yaml) описывает реальные HTTP-границы. Версия 1 поддерживает provider=ollama (нативный протокол) и provider=openai (OpenAI-совместимый протокол, не ограниченный одним hostname), D-65/D-66. Полная совместимость любого стороннего сервера по названию не утверждается.

| Provider | Endpoint относительно parameters.base_url | Тело | Из ответа используем |
|---|---|---|---|
| ollama | /embed | model, input, обязательное truncate:false; поддержанные dimensions/keep_alive/options при наличии | embeddings в порядке входов |
| openai | /embeddings | model, input, encoding_format:float; поддержанное моделью dimensions при наличии | data[].index и data[].embedding |

parameters.base_url — существующий служебный параметр клиента, не передаётся в JSON-тело модели. Примеры API-префиксов: http://localhost:11434/api и https://api.openai.com/v1; они не назначаются скрытыми defaults. Рабочее допущение для формальной схемы конфигурации: адрес задаётся явно; URI без HTTP(S), с userinfo или неполным адресом отклоняется локально. Новые поля/колонки не вводятся.

Provider/model/parameters заменяются целиком, без merge, D-69. Model/input/encoding_format/обязательное truncate задаются клиентом; параметры не могут подменить вход и разрешить усечение. Адаптер использует только документированные параметры своего протокола. Credentials отсутствуют в parameters; OPENAI_API_KEY читается из окружения процесса CLI (drain наследует окружение запустившего вызова) и для openai используется в Authorization: Bearer. Локальному Ollama этот ключ автоматически не передаётся. Значение ключа не сохраняется и не выводится; тело ответа/заголовки provider не копируются вслепую в errors.

Ответ проверяется: число векторов равно числу входных текстов, все числа конечны, длина каждого вектора совместима с активной моделью/индексом; для совместимого ответа index должен однозначно покрывать входы, независимо от порядка data. Некорректный ответ — ошибка вычисления, не успешный пустой embedding. Usage и серверные тайминги не обязательны для порта. Специфика model-specific подготовки текста остаётся в mechanics/проверке качества, purpose и отдельный document/query-параметр не вводятся.

## Timing and limits
2026-10-19, [D-83](../decisions.md#D-83): assumed внутренний client deadline 60s на одну попытку, без нового config поля. Это граница ожидания HTTP клиента, не отсечка всего search/reindex. Timeout → embedding_failed; query продолжает FTS, фоновые attempts/max_retries сохраняются. Снятие ожидания клиента не обещает остановку remote compute. Неявные environment proxies/redirects отключены; HTTPS сертификат проверяется, выбранный HTTP endpoint не получает гарантии конфиденциальности транспорта. Клиент — блокирующий `ureq` 3 без async runtime (D-96): `max_redirects(0)`, прокси из окружения не читаются, таймаут попытки 60 s, TLS — rustls с `rustls-platform-verifier` (системное хранилище сертификатов); повторы и attempts — код letopis, не клиента. Проверка DR-5/DR-8 ещё не выполнена.

Исправление совместимости #49: каждый provider POST явно передаёт
`Connection: close`. Это предотвращает небезопасный reuse закрывающихся
HTTP/1.0-соединений в закреплённом ureq, включая ответы без явного close header.
Постоянное соединение HTTP/1.0 требует согласованного keep-alive
([RFC 9112 §9.3](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.3)).
Payload, auth, TLS validation, deadline и attempts не меняются; цена — новое
TCP/TLS-соединение на запрос. Это реализационная поправка по независимому ревью,
не измеренное обещание real-provider throughput.

Согласно [D-107](../decisions.md#D-107), один drain отправляет до четырёх
однотекстовых запросов через прежний синхронный client; provider batching не
добавляется. `EmbeddingProvider` разделяется между worker threads как
`Send + Sync`, без доступа к storage/files. Ограничение относится к документной
работе одного drain, не к query embedding других CLI. Координатор резервирует
попытки до HTTP и публикует ответы по готовности; завершённый, ещё не обработанный
ответ сохраняет занятое место. Config/CLI/JSON schemas не меняются. Сильные
гарантии при перестановке ответов, границы cleanup и ошибках заданы в MC-3/MC-5.

Вычисление — вне транзакции БД. Публикация изменений, сброс после смены `.letopis/config.json` и reindex фиксируют свой результат без ожидания векторов, D-7/D-69/D-71; условный сброс по предварительно наблюдавшейся identity и его атомарные эффекты определены один раз в [MC-3](../mechanics.md#mc-3--embeddings-работа-из-данных-и-попытки). Конфликт не меняет векторы/попытки, не вызывает provider и не запускает повторный reset в том же вызове; drain перед записью результата или ошибки сверяет meta.config_identity и при несовпадении завершается. Отдельной очереди нет: работа — поисковые тексты без вектора; drain перед вызовом модели перечитывает файл и пропускает текст, чей search_hash изменился, а поздний результат хранится под прежним search_hash и не представляет новый текст ([D-95](../decisions.md#D-95)). Пока конфигурации нет, вычисление не запускается, индексация/граф/FTS работают, config возвращает result:null, D-70. Валидный `enabled:false` также не запускает inference/reset/drain, сохраняет векторы и попытки и оставляет поиск на FTS; identity считается только по четырём настроенным полям ([D-104](../decisions.md#D-104)).

Для native Ollama обязательное truncate:false обеспечивает отказ при превышении контекста. Совместимый Ollama endpoint не используется из-за ограничения, проверенного в [R-7](../research/R-7-embedding-api-compatibility.md). Молчаливое усечение и автоматическое дробление запрещены. Размер/квоты зависят от provider/model; численного общего батча или срока обработки очереди не вводится. Документированные пределы OpenAI не переносятся на Ollama и другие серверы. x-limits пуст: в текущем resource-math нет численных L; вместимость и сквозной поиск остаются not assessed. Одна синтетическая размерность примера не задаёт модель или формат vec1.

## Errors and retry
Нативный error, совместимый error.message, не-JSON ответ, неверный вектор, транспортный сбой, отказ авторизации/отсутствие требуемого ключа и превышение контекста отображаются в существующий embedding_failed с безопасным сообщением. Используются прежние ограниченные ретраи и failed после исчерпания; постоянный кэш результатов, новый статус и автоматическая бесконечная попытка не вводятся. Предел дополнительных попыток для одного поискового текста — max_retries из конфигурации по D-78, он не отправляется провайдеру. Резервирование попытки до вычисления и задержки описаны в MC-3; бюджет сохраняется через restart/SIGINT и действует между сбросами identity или удалением vectors.db; немедленный failed для отдельных классов ошибок не принят.

Если не вычислен embedding знания, сохранённые документ/graph/FTS остаются; старый несовместимый вектор не используется, ошибка видна через status (D-61). Ошибка query embedding ведёт к обычному FTS-поиску с успешным JSON; последняя ошибка хранится строкой query_error(at, error) в vectors.db и видна в status до следующего успешного embedding запроса (D-62, [D-95](../decisions.md#D-95)); при валидном disabled config она скрыта, но сохранена. Ошибка после успеха reindex не меняет его результат (D-71). Отмена связанного поискового запроса использует существующий cancelled (SIGINT прерывает ожидание HTTP, D-96), не останавливая фоновую работу проекта.

Проверка вложенной `.letopis/config.json` при вызове локальна, включая disabled provider settings, обязательного inference нет; плоский старый файл требует ручной миграции, команда config только показывает файл (D-95, [D-104](../decisions.md#D-104)). Новый ключ действует со следующего запуска drain: окружение процесса CLI, drain наследует окружение запустившего вызова (рабочее допущение); отдельная горячая ротация/.env/хранилище ключей не добавляется. Новый запуск drain не обнуляет счётчик попыток и не возобновляет failed автоматически.

## Результаты TK-6

2026-10-21: [transport harness и evidence](../checks/TK-6/report.md) — PASS на macOS/Linux glibc ARM64: по 8 Rust и 19 Python тестов, 10/11 compiling negative controls. Проверены обе формы API, HTTP 200 и обязательные поля, число/размерность/конечные f32 и индексы, настоящий deadline 60 s, silent headers/body/trickle, SIGINT, безопасные ошибки и отсутствие redirect/environment proxy. Linux-прогон выполнен с `--network none`.

Системный CA принят и hostname mismatch отвергнут в disposable Linux-контейнере; на macOS отдельно проверен публичный HTTPS endpoint через тот же Agent factory, без изменения Keychain. Реальные модели, минимальная совместимая версия Ollama, произвольные compatible servers и полные DR-5/DR-8 этим стендом не подтверждены; итоговые drills остаются TK-41. Это boundary proof выбранного адаптера, а не production-интеграция.

## Verification and sources
Проверено чтением 2026-10-18: [Ollama /api/embed](https://docs.ollama.com/api/embed) — model/input, embeddings, truncate:false и входные параметры; [OpenAI create embeddings](https://developers.openai.com/api/reference/resources/embeddings/methods/create) — model/input, float encoding, data/index/embedding и условная поддержка dimensions; [Ollama compatibility](https://docs.ollama.com/api/openai-compatibility) и закреплённый код — R-7. Verified означает проверку описанного протокола по источникам; вызовы модели, работоспособность letopis, соответствие произвольного совместимого сервера и ресурсные цели не проверены этим статусом. Перед подключением другого совместимого сервера проверяется требуемое подмножество и отсутствие молчаливого усечения.

2026-10-19, [D-78](../decisions.md#D-78): max_retries обязателен в полном объекте конфигурации и его ответе; 0 означает только первую попытку, 3 — до четырёх попыток всего. Параметр не является частью HTTP-body провайдера. До настройки конфигурация остаётся null. Изменение любого поля, в том числе только этого, меняет identity файла и сбрасывает векторы и попытки ([D-95](../decisions.md#D-95)).
