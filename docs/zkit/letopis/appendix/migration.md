# letopis — отчёт адаптации к zkit

> **Status:** draft · **Date:** 2026-10-18

## Что изменено
Классификация MoSCoW в новых таблицах предварительная: пользователь не проводил отдельную приоритизацию. Метка Should у критериев пользы не снимает условие их проверки.

Существующая работа разложена в `docs/zkit/letopis/`: concept/requirements/contracts/data/architecture/mechanics, единый decisions и исследования. Доменная модель, сценарии, аудит и физическая модель сохранены как подробные дополнения. Ранний исходный requirements сохранён в reference как исторический документ; актуальные требования получили FR/NFR/C. В корне docs не остаются параллельные копии старых файлов. Пути исследований исправлены; исходники и результаты проб не меняются.

Номера D/FR/E/B/MC добавляют навигацию и трассировку, не новые продуктовые интерфейсы. Точная карта каждого исходного файла и SHA-256 до переноса находятся в [манифесте](migration-manifest.json). Старые JSON-примеры проверяются на полное совпадение разобранного содержимого.

Статус `draft` этапа не отменяет отдельные решения со статусом «принято (перенесено)». Обратное тоже верно: принятый стек не доказывает закрытую готовность всего этапа. Flow найдёт первый draft/missing; вернуться означает закрыть отмеченный разрыв, а не повторить всё интервью. Автоматически утверждать новые документы нельзя.

<a id="open-questions"></a>
## Открытые вопросы
1. Последнее предложение: одна защищённая фаза сохранения на проект или несколько. Пользователь ещё не ответил; ни один вариант не внесён в принятые решения. Продолжение обсуждения хранения сохраняется здесь.
2. Физическая запись восстановления: ключ/число строк, область прежнего Git-снимка и порядок fsync объектов, refs, файлов/каталогов и SQLite. Hash/snapshot/paths и TEXT JSON-массив paths уже приняты; element_ids не возвращаем.
3. **Закрыто 2026-10-18 по [D-30](../decisions.md#D-30):** в v1 только create/edit/delete размеченных элементов. Общие патчи, замены текста и произвольные вставки исключены. Ранние материалы сохранены как история, а окончательная JSON Schema остаётся отдельной незавершённой работой.
4. Нагрузка, число/размер элементов и связей, локальная модель, размерность и рабочая память; подтверждение времени поиска. Не додумывать числа ради расчёта.
5. Полный DDL, ранжирование FTS/векторов, retry/backoff, credentials/provider, резервное копирование служебного реестра source и retention диагностик. Уже выбранные колонки/ограничения SQL сохраняются.
6. Некоторые ранние абзацы подробных документов противоречат поздним уточнениям. Применять реестр: без метарёбер и исторического резерва UUID, без бессрочного кэша apply, без ожидания всех embeddings и watcher, без отдельной истории оснований в БД. Старые примеры/формулировки сохранены для сверки; это не новая развилка.

## Как продолжать
В репозитории letopis вызывать `/zkit:flow` для проекта `letopis`. Он увидит формальные draft и незаполненные этапы. Закрывать их по одному, используя уже принятые D-n. Дизайн можно подробно уточнять дальше, но результаты measurements, схемы или модели нельзя помечать проверенными до их выполнения. Эта миграция не запускает реализацию.

Эти четыре design ERROR (два архитектурных и два механики) оставлены видимыми. Исправлять их добавлением неподтверждённых решений либо фиктивного доказательства нельзя. Предупреждения архитектуры о draft входе и технологических словах в старом тексте остаются: выбранные технологии уже приняты, исходный подробный материал сохранён. Нулевые новые утверждения о нагрузке/долговечности не выводятся из exit 0. Проверка migrated JSON означает синтаксис/сохранность примеров, а не соответствие ещё отсутствующей полной схеме.

Независимый reviewer проверил новый слой concept/requirements/decisions/data/mechanics и префиксы architecture/contracts. Вердикт: небольшие замечания, без существенного нарушения принятых решений. Исправлены обе находки: предварительный Should явно не является согласованным понижением приоритета; B-6 StateService трассируется только к состоянию/ошибкам, не к поставке навыка, переносимости и пользе продукта. Протокол последовательного сохранения остался открытым.

Проверка переноса не выполняет продуктовый код, нагрузочные испытания или новые Go/Rust-пробы. Git staging/commit этой миграцией не выполняются.
