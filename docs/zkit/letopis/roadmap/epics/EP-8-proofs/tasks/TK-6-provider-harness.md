## 1. Цель

До основного build нужно проверить рискованные примитивы на узком воспроизводимом сценарии и получить основание для G-0. Конкретный результат этой задачи: boundary harness двух API с воспроизводимыми негативными transport-сценариями.

## 3. Что сделать

1. Реализовать минимальные вызовы Ollama и OpenAI-совместимого embedding API в harness.
2. Подать malformed/неполные vectors, молчащий endpoint, ошибки и отмену.
3. Проверить deadline, локальный режим и безопасную диагностику без response body/секретов.

## 4. Ожидаемый результат

Boundary harness двух API с воспроизводимыми негативными transport-сценариями.

## 5. Критерии приёмки

- [ ] Harness Ollama и OpenAI-совместимого API проверяет форму vectors, silent endpoint, deadline/cancel и безопасные ошибки без ключа/response body.
- [ ] local mode не использует внешний endpoint.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

## 7. Границы

- **Входит:** Boundary harness двух API с воспроизводимыми негативными transport-сценариями. Работа и собственные проверки перечислены в разделе 3.
- **Не входит:** Production provider port/executor — [TK-13](../../EP-1-thin-slice/tasks/TK-13-embeddings.md); lifecycle retries — [TK-27](../../EP-3-maintenance/tasks/TK-27-embedding-lifecycle.md); полный offline/security drill — [TK-41](../../EP-4-system-validation/tasks/TK-41-provider-drill.md).
- **Интерфейсы — вход:** [TK-1](TK-1-build.md): Воспроизводимый build harness и отчёт о совместимости выбранной связки на двух ОС
- **Интерфейсы — выход:** Результат раздела 4 и воспроизводимые проверки получают [TK-7](../../EP-1-thin-slice/tasks/TK-7-markdown.md), [TK-13](../../EP-1-thin-slice/tasks/TK-13-embeddings.md), [TK-41](../../EP-4-system-validation/tasks/TK-41-provider-drill.md).

## 8. Риски и примечания

**Основание оценки 4 / 8 / 16 ч:** best — transport fixtures и доступный Ollama подходят выбранному контракту; expected включает работу раздела 3, собственные проверки и передачу результата; неопределённость worst — отмена молчащего endpoint, некорректные ответы и безопасная обработка ошибок двух API. Это инженерный диапазон, не измеренная скорость.

**Риск и действие:** Отмена молчащего endpoint, некорректные ответы и безопасная обработка ошибок двух API. Зафиксировать воспроизводимый failing case и ограничить исправление указанной границей; если требуется смена принятого дизайна или работа выходит за worst — поставить blocked, вернуть решение на соответствующий gate и пересчитать план. Ожидание оборудования/весов не маскировать рабочими часами.
