# EP-8 — Риски выбранных механизмов

> **Фаза:** PH-0
> **Оценка, ч:** 22 / 46 / 92 (best / expected / worst)
> **Зависимости:** —

## Цель

Воспроизводимые узкие доказательства выбранных примитивов и протокол пилота позволяют принять решение G-0 до production-интеграции.

## Границы

- **Входит:** Воспроизводимые узкие доказательства выбранных примитивов и протокол пилота позволяют принять решение G-0 до production-интеграции. Выполняются только задачи, перечисленные ниже.
- **Не входит:** Production-интеграция принадлежит EP-1; target-scale RAM и ранний пилот — EP-7; физические и полные системные испытания — EP-4.
- **Интерфейсы:** точные входы/выходы и ссылки на потребителей заданы в карточках. Эпик не вводит отдельный процесс или runtime-сервис.

## Задачи

Разделение следует проверяемым механизмам и артефактам, а не слоям design/code/test. Порядок определяется зависимостями и [недельным планом](../../../roadmap.md); G-0 закрывается последней задачей фазы.

- [TK-1 — Проверить сборку Rust/SQLite/FTS5/vec1 на macOS/Linux](tasks/TK-1-build.md): Воспроизводимый build harness и отчёт о совместимости выбранной связки на двух ОС.
- [TK-2 — Проверить публикацию по файлу и прерывание процесса](tasks/TK-2-durability-harness.md): Матрица прерываний публикации с точным oracle и воспроизводимый harness обнаружения/публикации.
- [TK-3 — Проверить vec1 reset, read snapshot и пропуск устаревшего текста](tasks/TK-3-vector-harness.md): Регрессионные сценарии vec1/read view и пропуска устаревшего текста по search_hash.
- [TK-4 — Проверить flock и запуск drain](tasks/TK-4-runtime-harness.md): Проверенная координация процессов: одна публикация, один drain, отмена SIGINT с negative fixtures.
- [TK-5 — Подготовить воспроизводимый протокол пилота](tasks/TK-5-pilot-protocol.md): Исполнимый протокол P-1 и формы отчёта для раннего и финального пилота.
- [TK-6 — Проверить embedding transport и offline ошибки](tasks/TK-6-provider-harness.md): Boundary harness двух API с воспроизводимыми негативными transport-сценариями.

## Приёмка

Все критерии [TK-1](tasks/TK-1-build.md), [TK-2](tasks/TK-2-durability-harness.md), [TK-3](tasks/TK-3-vector-harness.md), [TK-4](tasks/TK-4-runtime-harness.md), [TK-5](tasks/TK-5-pilot-protocol.md), [TK-6](tasks/TK-6-provider-harness.md) выполнены с evidence. Gate фазы отдельно закрывает её последняя задача; промежуточный эпик может передать готовые результаты задачам той же фазы до этого gate. Сам эпик не дублирует выполнение или часы дочерних задач.
