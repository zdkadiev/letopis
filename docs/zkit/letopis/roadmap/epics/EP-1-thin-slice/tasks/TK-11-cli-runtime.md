## 1. Цель

Сквозной путь должен соединить реальные адаптеры; ранние RAM и usefulness результаты нужны до расширения полного функционала. Конкретный результат этой задачи: рабочий CLI и один автоматически запускаемый worker проекта.

## 3. Что сделать

1. Реализовать bootstrap worker и локальный framed IPC по внутреннему контракту.
2. Подключить CLI apply/inspect к прикладным портам и общий JSON envelope.
3. Проверить неизвестные поля, exit codes, потерю соединения и запрет replay.

## 4. Ожидаемый результат

Рабочий CLI и один автоматически запускаемый worker проекта.

## 5. Критерии приёмки

- [ ] Автоматический bootstrap одного процесса проекта, framed IPC и apply/inspect проходят реальный вызов CLI.
- [ ] Один JSON stdout, exit 0/1, unknown fields reject.
- [ ] Нет replay потерянного ответа.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

## 7. Границы

- **Входит:** Рабочий CLI и один автоматически запускаемый worker проекта. Работа и собственные проверки перечислены в разделе 3.
- **Не входит:** Предметные read-алгоритмы — [TK-12](TK-12-search.md)/[TK-24](../../EP-2-knowledge/tasks/TK-24-inspect.md); полный cancel/waiter lifecycle — [TK-29](../../EP-3-maintenance/tasks/TK-29-cancellation.md); runtime proof уже в [TK-4](../../EP-8-proofs/tasks/TK-4-runtime-harness.md).
- **Интерфейсы — вход:** [TK-4](../../EP-8-proofs/tasks/TK-4-runtime-harness.md): Проверенный протокол одного worker и startup/recovery barrier с negative fixtures; [TK-9](TK-9-storage.md): Начальная схема SQLite и storage adapters для всех согласованных сущностей; [TK-10](TK-10-save-recovery.md): Production save/recovery путь атомарной группы изменений с optimistic conflict checks
- **Интерфейсы — выход:** Результат раздела 4 и воспроизводимые проверки получают [TK-12](TK-12-search.md), [TK-14](TK-14-thin-slice.md), [TK-29](../../EP-3-maintenance/tasks/TK-29-cancellation.md).

Это инженерный диапазон, не измеренная скорость.

Зафиксировать воспроизводимый failing case и ограничить исправление указанной границей; если требуется смена принятого дизайна или работа выходит за worst — поставить blocked, вернуть решение на соответствующий gate и пересчитать план. Ожидание оборудования/весов не маскировать рабочими часами.
