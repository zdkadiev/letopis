# TK-31 — Выполнить условие пилота без памяти

## 1. Цель

Предварительные модели и отдельные пробы не подтверждают реализацию: здесь нужны фактические результаты полного профиля и отказов. Конкретный результат этой задачи: полные baseline наблюдения финального пилота.

- [Архитектура и владельцы](../../../../architecture.md).

## 3. Что сделать

1. Выполнить выбранные цепочки baseline без межсессионной памяти.
2. Для каждой задачи сохранить проверку результата и все наблюдения/токены.
3. Отметить ошибки и незавершённые задачи без выборочного исключения из отчёта.

## 4. Ожидаемый результат

Полные baseline наблюдения финального пилота.

## 5. Критерии приёмки

- [ ] Baseline проходит отобранные цепочки без накопленной межсессионной памяти.
- [ ] Сохранены проверка корректности, повторные исследования/нарушения договорённостей и полный token usage.
- [ ] Незавершённые/ошибочные задачи не исключаются молча.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

## 7. Границы

- **Входит:** Полные baseline наблюдения финального пилота. Работа и собственные проверки перечислены в разделе 3.
- **Не входит:** Условие памяти — [TK-32](TK-32-memory-condition.md); сравнение и вывод о пользе — [TK-33](TK-33-pilot-analysis.md); смена протокола требует явного пересмотра.
- **Интерфейсы — вход:** [TK-30](TK-30-pilot-setup.md): Зафиксированный набор задач и окружения финального сравнительного пилота
- **Интерфейсы — выход:** Результат раздела 4 и воспроизводимые проверки получают [TK-32](TK-32-memory-condition.md), [TK-33](TK-33-pilot-analysis.md).

## 8. Риски и примечания

**Основание оценки 4 / 8 / 16 ч:** best — все девять задач проходят в подготовленном окружении; expected включает работу раздела 3, собственные проверки и передачу результата; неопределённость worst — невалидные сессии или потерянный token accounting требуют повторить конкретный прогон. Это инженерный диапазон, не измеренная скорость.

**Риск и действие:** Невалидные сессии или потерянный token accounting требуют повторить конкретный прогон. Зафиксировать воспроизводимый failing case и ограничить исправление указанной границей; если требуется смена принятого дизайна или работа выходит за worst — поставить blocked, вернуть решение на соответствующий gate и пересчитать план. Ожидание оборудования/весов не маскировать рабочими часами.

## 9. Отчёт о выполнении

Задача ещё не выполнялась. Критерии не отмечены; evidence отсутствует.

После выполнения заполнить здесь: фактический результат и изменённые файлы; выполненные проверки с исходами; ссылки на evidence; оставшиеся блокеры/отклонения. `done` допустим только при выполненных критериях. При препятствии поставить `blocked` и указать причину, следующий шаг и затронутые зависимости.
