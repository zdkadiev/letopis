## 3. Что сделать

1. При индексации проверять существование source_snapshot и равенство адресованных bytes: несовпадение — флаг source_changed, отсутствующий снимок — диагностика file:<путь> и флаг; найденный снимок закрепляется ref (D-93).
2. Правка с сохранённым прежним полем snapshot сохраняет основание; только явно записанный новый OID обновляет его. Удалённое поле означает отсутствие канонического основания, включая rebuild.
3. Проверить changed/not_found, C1/C2 с одинаковыми bytes и чтение истории из Git.

## 4. Ожидаемый результат

Проверка происхождения и оснований знания с корректными freshness flags.

## 5. Критерии приёмки

- [x] Доступный basis закреплён до публикации; check/search наблюдают несовпадение bytes как source_changed, отсутствующий root диагностируется без отказа индексации.
- [x] Edit с прежним полем snapshot сохраняет basis; новый OID, удаление поля и rebuild проверены по утверждённому уточнению.
- [x] Changed/not_found ставят live flags; знания/FTS сохраняются, stale независим.
- [x] Сервисный примитив сравнения C1/C2 с одинаковыми адресованными bytes даёт Equal; история остаётся в Git. Подключение JSON filters отложено до TK-22.

- [x] Соблюдены [структура программы и границы модулей](../../../../architecture.md#program-structure); в отчёте названы проверенные границы/файлы и evidence либо обосновано отсутствие изменений продуктового Rust-кода.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

**Архитектурная проверка:** выполнить [общий порядок проверки структуры](../../../../architecture.md#program-structure-review) для изменяемых компонентов и зафиксировать результат в отчёте; область без изменений продуктового Rust-кода указать явно.

**Риск и действие:** Сравнение разных trees с одинаковыми bytes, исчезнувшие источники и сохранение прежнего основания.
