## 1. Цель

Нужно довести принятые контракты и инварианты до полного v1 scope, сохранив общий путь сохранения/чтения. Конкретный результат этой задачи: полный доменный валидатор графа с ошибками по файлу.

## 3. Что сделать

1. Завершить разбор файл-элементов и раздел-элементов с якорями, уникальность якорей и запрет вложенности; kind выводится: метавершина — элемент с исходящими includes (D-95).
2. Находить запросом в check/status висячие ссылки, петли и includes-циклы через файлы; traverse берёт только рёбра с существующей целью и не заходит повторно в посещённые узлы.
3. Проверить, что ошибка одного файла не блокирует остальные и check не меняет файлы.

## 4. Ожидаемый результат

Полный доменный валидатор графа с ошибками по файлу (D-95).

## 5. Критерии приёмки

- [ ] ID path и path#anchor стабильны при вставке строк; дубль якоря и вложенный элемент — ошибка файла.
- [ ] Висячая ссылка, петля и косвенный includes-цикл видны в check/status, пока причина существует; появление цели убирает проблему без правки файла-источника; traverse не зацикливается и не возвращает несуществующие цели.
- [ ] check не меняет файлы.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

## 7. Границы

- **Входит:** Полный доменный валидатор графа с ошибками по файлу. Работа и собственные проверки перечислены в разделе 3.
- **Не входит:** Грамматика — [TK-7](../../EP-1-thin-slice/tasks/TK-7-markdown.md); публикация — [TK-10](../../EP-1-thin-slice/tasks/TK-10-change-detection.md); check/удаления/переименования — [TK-19](TK-19-check-renames.md); source identity — [TK-20](TK-20-source-identity.md).
- **Интерфейсы — вход:** [TK-17](../../EP-7-early-validation/tasks/TK-17-early-pilot.md): Отчёт раннего пилота и решение, допустимо ли расширять slice до полного scope; [TK-7](../../EP-1-thin-slice/tasks/TK-7-markdown.md): Доменная модель и parser Markdown (без сериализатора: letopis не пишет корпус, D-93), отделённые от Git/SQLite/CLI адаптеров; [TK-10](../../EP-1-thin-slice/tasks/TK-10-change-detection.md): Production путь обнаружения изменений и публикации по файлу
- **Интерфейсы — выход:** Результат раздела 4 и воспроизводимые проверки получают [TK-19](TK-19-check-renames.md), [TK-20](TK-20-source-identity.md), [TK-23](TK-23-traversal.md).
