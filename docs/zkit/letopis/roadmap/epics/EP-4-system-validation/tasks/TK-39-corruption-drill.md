Предварительные модели и отдельные пробы не подтверждают реализацию: здесь нужны фактические результаты полного профиля и отказов. Конкретный результат этой задачи: corruption/freshness отчёт DR-3/DR-4 и доказательство координированного C-8 сценария.

## 3. Что сделать

1. Раздельно повредить Git objects, SQLite-кэш и vectors.db целиком.
2. Проверить внешнюю Git-смену, invalid markup/source, freshness и исправление причины.
3. Выполнить Git checkout/rebase во время работы агентов и проверить, что следующий вызов публикует итоговое состояние по файлу (D-93).

## 4. Ожидаемый результат

Corruption/freshness отчёт DR-3/DR-4 и доказательство координированного C-8 сценария.

## 5. Критерии приёмки

- [ ] Missing Git object даёт fail-closed, повреждённый или удалённый кэш — rebuild без потери source identity.
- [ ] Внешняя Git-смена/invalid markup/удалённый source дают flags и последний корректный индекс.
- [ ] Исправление убирает проблему из status.
- [ ] Git checkout во время работы агентов обнаруживается следующим вызовом как обычные изменения файлов.
- [ ] После Git следующий CLI валидирует снимок, без перехвата произвольного Git.

- [ ] Невалидный A рядом с валидно изменённым B: B опубликован, A сохраняет прежнюю проекцию; исправление A убирает его ошибку из status (D-95).

- [ ] Соблюдены [структура программы и границы модулей](../../../../architecture.md#program-structure); в отчёте названы проверенные границы/файлы и evidence либо обосновано отсутствие изменений продуктового Rust-кода.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

**Архитектурная проверка:** выполнить [общий порядок проверки структуры](../../../../architecture.md#program-structure-review) для изменяемых компонентов и зафиксировать результат в отчёте; область без изменений продуктового Rust-кода указать явно.
