## 3. Что сделать

1. Offline получить согласованную внешнюю копию Git/Markdown и `.letopis/config.json`; БД и vectors.db не копировать.
2. Восстановить её на чистом устройстве без доступа к исходному диску.
3. Проверить пересборку кэша reindex (source ID/created_at из ссылок, drain считает тексты без вектора) и признание recovery point копии.

## 4. Ожидаемый результат

Воспроизводимый внешний backup/restore drill Git/Markdown и `.letopis/config.json` с пересборкой кэша (D-91).

## 5. Критерии приёмки

- [ ] Offline копия Markdown, реального Git object/ref closure и config.json восстановлена без исходного диска.
- [ ] Config восстановлен; кэш пересобран, source ID/created_at совпадают с выведенными из ссылок.
- [ ] Старый recovery point признан, RPO/RTO не выдуманы.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

## 7. Границы

## 8. Риски и примечания

**Основание оценки 3 / 6 / 12 ч (пересчёт 2026-10-20):** после D-91/D-93 копируются только Git/Markdown и config.json, БД не восстанавливается; best — согласованная offline копия и чистое устройство доступны; expected включает работу раздела 3, собственные проверки и передачу результата; неопределённость worst — восстановление полного Git closure с недоступным исходным диском. Это инженерный диапазон, не измеренная скорость.

**Риск и действие:** Восстановление полного Git closure с недоступным исходным диском. Зафиксировать воспроизводимый failing case и ограничить исправление указанной границей; если требуется смена принятого дизайна или работа выходит за worst — поставить blocked, вернуть решение на соответствующий gate и пересчитать план. Ожидание оборудования/весов не маскировать рабочими часами.
