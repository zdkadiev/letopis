# TK-25 — Реализовать full/selective reindex и Git detection

## 1. Цель

Нужно довести принятые контракты и инварианты до полного v1 scope, сохранив общий путь сохранения/чтения. Конкретный результат этой задачи: координатор reindex и Git detection без фонового watcher.

## 3. Что сделать

1. Реализовать первичное, full и selective reindex через согласованные снимки.
2. Обнаруживать внешнюю Git-смену при CLI-вызове и обновлять затронутые элементы.
3. Проверить последний корректный индекс при invalid corpus и завершение без ожидания vectors.

## 4. Ожидаемый результат

Координатор reindex и Git detection без фонового watcher.

## 5. Критерии приёмки

- [ ] Первый вызов строит graph/FTS и ждёт, selective пересчитывает затронутые элементы.
- [ ] Внешняя Git-смена замечается при вызове без watcher.
- [ ] Невалидная публикация сохраняет последний корректный индекс, reindex не ждёт vectors и не меняет подтверждённое основание.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

## 7. Границы

- **Входит:** Координатор reindex и Git detection без фонового watcher. Работа и собственные проверки перечислены в разделе 3.
- **Не входит:** Полный embedding lifecycle — [TK-27](TK-27-embedding-lifecycle.md); отмена/CLI waiter integration — [TK-29](TK-29-cancellation.md); watcher в v1 не добавляется.
- **Интерфейсы — вход:** [TK-24](../../EP-2-knowledge/tasks/TK-24-inspect.md): Полный batch inspect и рабочий навык чтения/записи перед G-2; [TK-10](../../EP-1-thin-slice/tasks/TK-10-save-recovery.md): Production save/recovery путь атомарной группы изменений с optimistic conflict checks; [TK-13](../../EP-1-thin-slice/tasks/TK-13-embeddings.md): Базовый embedding runtime и обработчик долговечных jobs
- **Интерфейсы — выход:** Результат раздела 4 и воспроизводимые проверки получают [TK-26](TK-26-corruption.md), [TK-27](TK-27-embedding-lifecycle.md), [TK-29](TK-29-cancellation.md), [TK-30](../../EP-5-final-pilot/tasks/TK-30-pilot-setup.md), [TK-36](../../EP-4-system-validation/tasks/TK-36-disk-growth.md), [TK-39](../../EP-4-system-validation/tasks/TK-39-corruption-drill.md).

## 8. Риски и примечания

**Основание оценки 4 / 8 / 16 ч:** best — готовые snapshot/projection/validator порты дают один согласованный вход; expected включает работу раздела 3, собственные проверки и передачу результата; неопределённость worst — сдвиг координат, обнаружение Git-смены и отказ публикации невалидного корпуса. Это инженерный диапазон, не измеренная скорость.

**Риск и действие:** Сдвиг координат, обнаружение Git-смены и отказ публикации невалидного корпуса. Зафиксировать воспроизводимый failing case и ограничить исправление указанной границей; если требуется смена принятого дизайна или работа выходит за worst — поставить blocked, вернуть решение на соответствующий gate и пересчитать план. Ожидание оборудования/весов не маскировать рабочими часами.
