## 3. Что сделать

1. Установить и проверить полный навык из TK-29 в поставке TK-43; сверить существующие JSON-примеры с установленным CLI, без повторной реализации его содержания.
2. Сверить инструкции snapshots/live reads, висячих ссылок/перепроверки, config.json как файла/cancel/status и добавить эксплуатационный внешний restore по evidence TK-40.
3. Дать исполнимый C-8 порядок координации и проверить documented scenario новым агентом.

## 4. Ожидаемый результат

Готовый coding-agent skill и проверенная эксплуатационная документация поставки.

## 5. Критерии приёмки

- [ ] Установленный coding-agent skill покрывает все CLI JSON входы/выходы, snapshots/live reads, висячие ссылки/потерю ответа/перепроверку, status/cancel/config.json как файл и внешний backup/restore.
- [ ] Новый агент выполняет documented scenario.
- [ ] Эксплуатация с Git: правки через Git обнаруживаются следующим вызовом (D-93); backup — Git/Markdown и config.json; затем возобновляет CLI со сверкой.
- [ ] Никакого Git interceptor/новых команд/сервисов/ACL.

## 6. Как проверить

1. Выполнить сценарии из разделов «Что сделать» и «Критерии приёмки» на подготовленных входах; для изменения кода запустить соответствующие unit/integration/contract checks созданной реализации.
2. Для каждого критерия записать команду или последовательность действий, ожидаемый исход и фактический результат; сверить отрицательные/аварийные случаи, прямо перечисленные в критериях.
3. Приложить минимальные воспроизводимые evidence: версию сборки, платформу/конфигурацию, входы и результаты. Ещё не существующие CLI/test targets не объявлять запущенными; точные команды появятся вместе с реализацией.

**Основание оценки 4 / 8 / 12 ч:** best — проверенный полный навык и протоколы требуют только поставки и сверки примеров; expected включает работу раздела 3, собственные проверки и передачу результата; неопределённость worst — расхождение installed CLI и примеров, непонятные новому агенту шаги эксплуатации. Это инженерный диапазон, не измеренная скорость.

**Риск и действие:** Расхождение installed CLI и примеров, непонятные новому агенту шаги эксплуатации. Зафиксировать воспроизводимый failing case и ограничить исправление указанной границей; если требуется смена принятого дизайна или работа выходит за worst — поставить blocked, вернуть решение на соответствующий gate и пересчитать план.
