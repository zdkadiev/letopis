# TK-18/19 Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish TK-18/19 by exposing current diagnostics through a complete, observational CLI status response.

**Architecture:** A StatusService reads one optional published storage view, reusing check's diagnostic rules. Filesystem observations remain behind application interfaces; the CLI calls a service and lib.rs constructs the collaborators. Status does not refresh, synchronize vector identity, infer, or launch drain.

**Tech Stack:** Existing synchronous Rust toolchain, rusqlite, SeaQuery, serde, confined filesystem operations, native SQLite/vec1. No dependency/schema change.

**Spec:** [Approved design](../specs/2026-10-26-tk-18-19-status-design.md), approved by user “go on” on 2026-10-26. Baseline main `0f8f92b`; design commit `04d0500`; branch/worktree `tk-18-19-status`.

## Global Constraints

- Preserve unrelated worktrees; all implementation stays in this task worktree.
- Complete X-1 fields: revision, embedding_backlog, embedding_failed, locks, problems.
- No placeholders, refresh, vector reset, inference, drain launch or lock-owner PID writes.
- Count distinct current knowledge search_hash values; source/orphan rows are excluded.
- No published cache: revision null, zero published counts, no cache-derived findings; config/lock observations still run.
- Unavailable/invalid/mismatched config: every current distinct hash is backlog, failed zero; no reset. Invalid/unreadable config adds a safe problem. Query_error remains visible.
- Busy locks report best-effort recorded positive PID, including the documented takeover race; invalid/unreadable PID is an error.
- One database read view, no atomic promise across database, live config, Git observations and lock probes.
- Keep KISS/DRY/YAGNI and AGENTS.md boundaries, signatures, visibility, function sizes and documentation rules.
- No TK-16/17 runs, paid inference, TK-26/27 acceptance or all-TK-28 completion claim.
- Each task: RED, minimal GREEN, focused manual mutation, restore, focused checks, intended-path commit. Keep output concise.

## Review Focus

- A lock may be busy while its PID is stale/invalid: Task 2 pins the supported best-effort semantics without blocking.
- Cache or vectors may be absent independently: Task 1 returns measured published state without creating either file.
- Config can change after its bytes are read: Tasks 1/3 use captured config and pinned identity without resetting or claiming live atomicity.
- Multiple knowledge IDs can share a hash or leave orphan vectors/failures: Task 1 pins distinct current-hash counts.
- A late error can follow valid diagnostics: Tasks 3/4 return one failure with no partial success or raw causes.

Proposed exact interfaces (all new public types implement Debug and document contracts):

```rust
pub struct StatusReport {
    pub revision: Option<u64>,
    pub embedding_backlog: u64,
    pub embedding_failed: u64,
    pub locks: Vec<HeldLock>,
    pub problems: Vec<CommandProblem>,
}
pub enum LockName { Index, Embed }
pub struct HeldLock { pub name: LockName, pub pid: NonZeroU32 }
pub enum EmbeddingStatusPolicy {
    Unavailable,
    Ready { identity: Sha256, max_attempts: u64 },
}
pub struct EmbeddingStatusSummary {
    pub backlog: u64,
    pub failed: u64,
    pub exhausted: Vec<EmbeddingFailure>,
}
pub trait StatusReader {
    fn read_status(&mut self) -> CommandResult<StatusReport>;
}
pub trait StatusStorage {
    type Read<'a>: StorageRead where Self: 'a;
    fn begin_status_read(&mut self) -> StorageResult<Option<Self::Read<'_>>>;
}
pub trait StatusFiles {
    fn read_config(&self) -> EmbeddingResult<Option<Vec<u8>>>;
    fn observe_locks(&self) -> CommandResult<Vec<HeldLock>>;
}
// Add to existing StorageRead:
fn read_embedding_status(
    &mut self, policy: &EmbeddingStatusPolicy,
) -> StorageResult<EmbeddingStatusSummary>;
```

Keep the required scoped storage generic. StatusService may use a second generic
for non-object-safe GraphDiagnostics, with other collaborators borrowed through
object-safe interfaces. Build/use it inside lib.rs command assembly so local
collaborators outlive the call; no Box/Arc/factory solely to return it.
`StatusDependencies<'a, S, G>` owns S and borrows G, StatusFiles,
SourceProvenance and EmbeddingProvider. `StatusService::new(deps)` performs no I/O.
Provider dependency is used only for existing local validate_config, never embed.
