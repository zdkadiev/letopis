# CLI `--help` / `--version` Implementation Plan

> **Amendment, 2026-10-28:** `config` was implemented after this plan and is now the seventh public help command. References below to hiding `config` and to six commands describe the original issue #53 scope and are superseded. The current stdin behavior is specified in [X-1](../../zkit/letopis/contracts/X-1-cli.md): terminal input is empty, and a non-terminal stream with no first byte within 250 ms is also empty.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `letopis --help`, `letopis <command> --help` and `letopis --version` print useful text and exit 0 without touching stdin, the repository or any service.

**Architecture:** A new `src/cli/help.rs` owns the static help texts and a pure `find_help(args) -> Option<String>` that recognises exactly three argv forms. `run_cli` calls it first and, on a hit, writes plain text via a new `output::write_text`; otherwise the existing `parse_request → run_request → write_response` path runs unchanged. `Request` and `parse_request` are not modified.

**Tech Stack:** Rust 2024 (pinned 1.95.0), std only, no new dependencies, no argument-parsing crate.

**Spec:** `docs/superpowers/specs/2026-10-28-cli-help-design.md` (read it first; also `AGENTS.md`).

## Global Constraints

- No new dependency (no clap); no async; no new trait or service. `Request`/`parse_request` untouched.
- Recognised argv, nothing else: `["--help"]`, `["--version"]`, `["<cmd>", "--help"]` with `<cmd>` in `check inspect search traverse reindex status`. Everything else (empty argv, `-h`, `-V`, `--help search`, `search --help x`, `embed --help`, `--version x`, non-UTF-8 argv) keeps today's JSON `invalid_request`, exit 1.
- Help goes to stdout as plain text (not a JSON envelope), exit 0; stderr stays empty. Write failure → exit 1, same as `write_response`.
- `--version` output is exactly `letopis 0.0.0\n`, built from `CARGO_PKG_NAME` / `CARGO_PKG_VERSION`; tests compare to a literal.
- `embed --drain` and `config` never appear in help.
- Help text is English, ≤ ~80 columns, no colour, no TTY detection.
- AGENTS.md style: caller above callee; public/`pub(crate)` items documented; verb names for functions; SCREAMING_SNAKE_CASE constants; functions ≤ 40 lines (60 hard); every test uses `// Given` / `// When` / `// Then`; no `unwrap`/`expect` in production code; mutation-check each new test (break code by hand, see test fail, restore).
- Commit messages carry no Claude/Anthropic attribution and no `Co-Authored-By` line (user's global rule overrides the harness reminder).
- Run commands from the worktree root `/Users/zdkadiev/Repos/letopis/.claude/worktrees/cli-help-53`.

## Review Focus

1. `letopis --help search`, `letopis search --help extra`, `letopis --version extra`, `letopis embed --help`, `letopis -h`, `letopis` (no args) must still return JSON `invalid_request` / exit 1 (Task 1 unit + Task 3 binary test).
2. Help works with an open, never-written stdin and in a non-Git empty directory, and creates no files (Task 3).
3. Stdout write failure on a help path returns exit 1, not 0 (Task 1).
4. A help example with a stale field name or missing required field is caught by feeding every example to `parse_request` (Task 2).
5. Non-UTF-8 argv does not panic and falls through to `invalid_request` (Task 1).

### Task 2: Real help content for every command

**Files:**
- Modify: `src/cli/help.rs`, `src/cli/help_tests.rs`

**Interfaces:**
- Consumes: `COMMANDS`, `CommandHelp`, `find_help` from Task 1; `parse_request(&[OsString], impl Read) -> CommandResult<Request>` in `src/cli/input.rs`.
- Produces: final texts. No signature changes.

Content to write (verify every format against the domain parsers `RepoPath`, `ElementAddress`/`KnowledgeId`/`SourceUri`, `TreeOid`, `EdgeType` and the input structs in `src/cli/input.rs` before writing; wording is yours):

- **General help**: `Usage` lines (`letopis <command> < request.json`, `letopis <command> --help`, `letopis --version`); one line per command; I/O contract — input is one JSON object on stdin (`{}` when no fields), unknown fields rejected; output is one JSON line `{"ok":true,"result":...}` (optional `warnings` array) or `{"ok":false,"error":{"code","message","details"}}`; exit 0 on `ok:true`, 1 otherwise; error codes `invalid_request not_found validation_failed embedding_failed internal_error cancelled`; run inside a Git repository; 2–3 `printf '%s\n' '<json>' | letopis <command>` examples (e.g. `search`, `check`, `traverse`).
- **check**: `paths` optional array of repo-relative paths (default whole corpus); result `{"errors":[Problem]}`, empty = valid; never writes files. Example `{}`.
- **inspect**: `element_ids` required non-empty array of addresses (`path.md`, `path.md#anchor`, `src/file.rs`, `src/file.rs#L2-L4`, http(s) URL); result `{"snapshot":"<git tree oid>","elements":{id:{path,lines?,hash}}}`; unknown id rejects the batch. Example `{"element_ids":["knowledge/decisions.md#cache"]}`.
- **search**: `query` string, `limit` integer ≥ 1, optional `filters` `{needs_recheck: bool, sources: [source URI], source_revisions: [full Git tree OID]}`; result array of `{element_id,path,lines?,revision,flags}` with flags `stale|source_changed|source_not_found`; metadata only, never file text. Example `{"query":"cache","limit":10}`.
- **traverse**: `element_ids` non-empty, `mode` `relations|containment|both`, `direction` `outgoing|incoming|both`, `depth` integer ≥ 0, `limit` ≥ 1, optional `edge_types` (lowercase names), optional `edge_limit` ≥ 1 (`edges` appear in result only when sent); start ids excluded from result. Example from `skills/letopis/SKILL.md`.
- **reindex**: input `{}`; rebuilds graph and full-text index; result `{"revision":N}`. Example `{}`.
- **status**: input `{}`; read-only; result `{revision|null, embedding_backlog, embedding_failed, locks:[{name,pid}], problems:[...]}`. Example `{}`.
