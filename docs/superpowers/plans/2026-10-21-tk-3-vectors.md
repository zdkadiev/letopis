## Review focus

1. A reader touches cache.db before reset but vectors.db afterward: mismatched identity must produce an explicit FTS-only outcome, not a wrong-dimension query.
2. An edit occurs before the live re-read, versus after the provider starts: the former spends no attempt; the latter can store only the old hash, never associate it with the new node hash.
3. A config reset occurs before reservation, during computation, or before a late failure: no stale attempt, vector or error may enter the new configuration.
4. Duplicate texts, source nodes and a stale candidate: duplicate text uses one vector, sources are excluded, and a skipped old hash cannot prevent other work or cause an infinite loop.
5. A crash occurs after reservation or inside key/vector publication: durable attempts and atomic key/vector/failure changes must survive without an orphan key or an extra provider call beyond the budget.

Public scratch interfaces (all fallible operations return `CheckResult<T>`):

```rust
struct Config { identity: String, model: String, max_retries: u32 }
struct WorkItem { id: String, search_hash: String }
enum StoreOutcome { Stored, ConfigChanged }
enum ReadOutcome { Vectors(Vec<String>), FtsOnly }
fn capture_config(root: &Path) -> CheckResult<Config>;
fn attached(root: &Path) -> CheckResult<rusqlite::Connection>;
fn pending(conn: &Connection, config: &Config, skipped: &BTreeSet<String>) -> CheckResult<Vec<WorkItem>>;
fn reserve(root: &Path, config: &Config, hash: &str) -> CheckResult<bool>;
fn store(root: &Path, config: &Config, hash: &str, vector: &[f32], checkpoint: &mut dyn FnMut(&str) -> CheckResult<()>) -> CheckResult<StoreOutcome>;
fn record_failure(root: &Path, config: &Config, hash: &str, error: &str) -> CheckResult<bool>;
fn search_vectors(conn: &Connection, config: &Config, query: &[f32]) -> CheckResult<ReadOutcome>;
fn drain(root: &Path, provider: &mut dyn FnMut(&str, &str) -> CheckResult<Vec<f32>>, checkpoint: &mut dyn FnMut(&str) -> CheckResult<()>) -> CheckResult<()>;
```

`pending` re-queries committed work each loop and deduplicates hashes; `reserve` returns false if exhausted or identity changed. Result storage verifies finite, nonempty vector values and uses one vectors.db transaction for key + native vector + deletion of the failure row. `search_vectors` checks identity within the reader's transaction, queries real vec1 without premature candidate limiting, joins by both vector rowid and node search_hash, and returns deterministically ordered fixture IDs. These are fixture interfaces, not domain ports.
