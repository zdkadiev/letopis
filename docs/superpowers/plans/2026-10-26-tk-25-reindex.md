# TK-25 Full Reindex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement full atomic reindex, share initial/incremental publication, and verify CLI-time external Git change detection.

**Architecture:** Extend the existing application-owned Refresher capability; keep one DocumentRefresher and one per-file projection/publish path. Full mode reparses every selected file under index.lock in one cache transaction, preserving last-valid invalid-file projections. CLI calls the capability; lib.rs wires concrete synchronous collaborators.

**Tech Stack:** Pinned Rust 1.95.0, SQLite WAL/FTS5 via rusqlite, existing SeaQuery, Git argv, kernel File::lock, existing detached drain. No new dependencies or schema.

**Spec:** [TK-25 design](../specs/2026-10-26-tk-25-reindex-design.md). User selected «По карточке»; fresh builder check found nothing important left. User approved this plan and Native execution on 2026-10-26. Implementation in progress; one fresh whole-branch review follows both tasks.

## Global Constraints

- KISS, DRY, YAGNI and [AGENTS.md](../../../AGENTS.md) apply to every task; no wrapper-only constructor bundles or speculative dispatch layers.
- Synchronous I/O; no new runtime, watcher, lifecycle state, selective paths, reindex --cancel or provider inference in reindex.
- Full reindex holds index.lock from candidate enumeration/preparation through one commit. Ordinary refresh retains no-op and changed-file-only behavior; initial publication uses full mode after redetection under lock.
- Process files sequentially; release each captured bytes/search text before the next. Existing metadata collections are allowed; no corpus text cache.
- Preserve last-valid invalid-file nodes/edges/contentless FTS and source_snapshot. No wholesale clear that loses them; physical corruption recovery belongs to TK-26.
- Full mode reparses hash-equal files and checks/retains their author-declared bases; no source_snapshot replacement, Git index/HEAD or Markdown writes.
- Pre-commit I/O/SQL/process failure rolls back graph/FTS/files/revision; late SIGINT does not undo commit. Handled cancelled JSON in all waits remains TK-29.
- One schema-valid JSON: reindex input {}, result {"revision": N}; no additional result fields, progress or document content.
- Reuse vectors by search_hash; do not wait for embed.lock, provider or drain completion. Use existing readiness/launch warnings without expanding lifecycle.
- Aim around 40 lines, maximum 60 per function/test/helper; top-down ordering, names as verbs, explicit imports, AAA, independent expected values, meaningful compiled mutations restored byte-for-byte.
- Keep historical evidence intact. G-1, resource/pilot results and unrun platforms are not certified by this task.

## Review Focus

1. Hash-equal full reindex must repair a deliberately missing FTS entry; incremental refresh must leave it alone until explicit reindex. Task 1 pins the difference with an independent FTS oracle.
2. Invalid A plus valid changed B retains A's previous FTS/edges/basis while B is published and later detected again. Task 1 also covers invalid A on fresh cache with no invented historical projection.
3. A publisher waiting behind reindex must redetect newer files; a pinned WAL reader must retain old revision/FTS until reopened. Task 1 uses process checkpoints and independent database observations.
4. Branch switch/reset changes tracked membership without watcher, including tracked ignored and missing candidates; observational status must not rebuild missing cache. Task 2 drives actual Git and CLI.
5. Reindex can finish while another process owns embed.lock and inference would stall; missing cache preserves matching vectors and authored basis. Task 2 proves completion without sleeps or real provider calls.
