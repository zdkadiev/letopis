# TK-1 storage build verification implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. The user approved the scope in chat on 2026-10-21.

**Goal:** Retain reproducible Rust/SQLite/FTS5/vec1 integration checks and real macOS ARM64 / Linux ARM64 results for TK-1.

**Architecture:** A standalone test crate under `tests/storage-build/` exercises small, file-backed temporary databases. A Python runner verifies the pinned vec1 source, compiles it against the bundled SQLite headers, and invokes Cargo tests; a pinned Linux image runs the same runner. Existing research is reference material, not modified or imported test data.

**Tech Stack:** Rust 1.95.0; rusqlite 0.40.2; libsqlite3-sys 0.38.2 / SQLite 3.53.2; native vec1 0.8 at SQLite commit a27bcfe21c9b4e0989e86eec8fb34a3832cd23c7; Python 3 and a C compiler.

**Spec:** [TK-1](../../zkit/letopis/roadmap/epics/EP-8-proofs/tasks/TK-1-build.md), plus the user's approved scope in chat.

## Global constraints

- SQLite 3.51.3+, WAL, synchronous=FULL, fullfsync on macOS, foreign_keys=ON.
- FTS5 contentless-delete and native vec1; no ANN/training or production storage implementation.
- vec1 SHA-256: a38c62274093bec34631831371ad433703d6dde7fa9ecd6088da4ed33d4a61f9.
- Fresh temporary databases only; no project or original research databases.
- Preserve the copied uncommitted design baseline. Do not commit another writer's changes.
- Claims cover the tested ARM64 targets only; no physical power-loss, load, or embedding-provider claims.

## Review focus

- A missing/invalid extension must fail rather than silently skip tests.
- Rolled-back inserts, updates, and deletes must leave both searchable contents and stored vectors unchanged.
- Extension loading must be disabled after registration, including on failure.
- Source checksum failures must precede compilation/loading of native code.
- Parallel/repeated runs must not reuse a database or platform binary.
