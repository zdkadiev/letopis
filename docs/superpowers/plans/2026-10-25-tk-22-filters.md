## Global Constraints

- “Different filter fields combine with AND.”
- “Values within `sources` or `source_revisions` combine with OR; duplicate values have no effect.”
- “An absent list and an empty list impose no restriction.”
- “Validate every requested revision before query inference and candidate-dependent exits, including empty query, empty corpus or selectors matching no sources.”
- Source identity is exact canonical SourceUri; file and range differ, URLs stay opaque/unfetched. Revisions are complete tree OIDs, never peeled commits or index counters.
- needs_recheck true/false/absent means any current X-1 flag/no current flag/no restriction. No flags does not certify truth or remote availability.
- Same-binding source/revision byte equality; missing addresses/bases and remote unknown do not match historical byte equality.
- Eligible channels rank before fusion and final limit; preserve reciprocal-rank sum, ID tie-break and no-filter output. No early SQL/vector limit or oversampling.
- Reuse observations for returned links, pinned graph metadata/bindings and existing config/query lifecycle. No broad error-to-fallback conversion or text/payload/secret output.
- “No query-embedding warning is added to search JSON.” Status UI remains TK-28; no pilot/resource/gate certification.
- Follow [AGENTS.md](../../../AGENTS.md) and [physical architecture/review](../../zkit/letopis/architecture.md#program-structure): service traits, concrete implementation files, synchronous I/O, scoped ownership, real lib.rs constructor wiring; no adapter cross-calls or new directory layers.
- New/touched code uses explicit imports, verbs, typed alternatives, public Debug/docs, focused 40/60-line methods, AAA tests and independent literal oracles. Hand mutations must fail at runtime and restore byte-for-byte; compilation failures alone do not count.
- Preserve other work and historical evidence. Use the existing shared Engram store with ENGRAM_DB=/Users/zdkadiev/Repos/letopis; guarded atomic recording, no direct DB edits.

## Review Focus

1. A valid requested tree listed with a missing tree must not hide the missing selector via OR short-circuit, empty query or no matching sources — Task 2 asserts not_found before a provider call.
2. Equal source addresses shared by two notes with different declared bases must be evaluated per knowledge/binding, without cross-candidate memoization — Task 2 expects exactly the matching note.
3. A source changes between predicate evaluation and link rendering — Task 2 uses a controlled observation count/return change and requires one observation with matching eligibility/flags.
4. A response succeeds after a previous query failure under the exact same config identity — Task 3 uses sequential fixture responses at one endpoint and requires query_error removal without a reset.
5. A filter excludes a candidate with corrupt/non-finite native rank data — Task 2 retains existing integrity error behavior instead of turning corruption into filtered success.
