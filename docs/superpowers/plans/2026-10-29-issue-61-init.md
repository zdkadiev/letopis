# Issue 61 Init Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `letopis init` and a schema-valid embeddings-disabled configuration without changing existing active configuration semantics.

**Architecture:** A configuration value distinguishes disabled from validated active settings in the service layer. `InitService` coordinates application-owned filesystem/storage capabilities; `lib.rs` wires concrete Git, filesystem and SQLite adapters, and `commands.rs` dispatches `init`. Filesystem owns no-clobber config publication; storage owns schema bootstrap.

**Tech Stack:** Pinned Rust toolchain, serde_json, rustix, rusqlite/SQLite, existing CLI and test fixtures.

**Spec:** `docs/superpowers/specs/2026-10-29-issue-61-init-design.md`

## Global Constraints

- Disabled file bytes: `{"enabled":false}\n`; active file keeps exactly its existing four root fields.
- No new provider, model default, runtime, lock, dependency, migration, or database state.
- Git work-tree validation completes before any service state is created.
- Existing valid config and database contents are preserved; unsafe or incompatible state is an error.
- Every new behavioral test uses Given/When/Then markers and is mutation-checked.
- Keep public diagnostics free of raw config content, credentials and endpoints.
- Product Rust changes require `make check` and `make verify`; storage-facing changes require a new host runner evidence directory.

## Review Focus

- A concurrent `init` loser must validate the winning file before success (Task 3).
- An existing symlink or nonregular config leaf must fail without following or replacing it (Tasks 2 and 3).
- A disabled file must never call provider validation, infer, or reset vector identity (Task 1).
- An unreadable file must not be mistaken for an absent one in `config` or `status` (Task 1).
- `init` outside Git must create nothing, even when an adjacent directory contains `.letopis/` (Task 3).
