# Упрощение типов сервисов — предложение

Статус: пользователь согласовал вариант B и план и поручил выполнение.
Перенос интерфейсов в service/mod.rs согласован и завершён отдельно.
Текущее изменение упрощает возвращаемые транзакции и параметры сервисов.


## Проблема

Пользователь считает объявления типов и дженериков чрезмерно сложными.
В текущем коде SearchService имеет шесть параметров типов,
DocumentRefreshService — пять. Storage и StatusStorage выбирают scoped capability
типы через Read<'a>, CacheWrite<'a> и VectorWrite<'a>. Эти типы связывают
заимствование транзакции с хранилищем; ограничение времени жизни нужно сохранить.

## Вариант A: сначала сократить параметры сервисов

Заменить параметры типов на обычные ссылки/владеющие trait objects у тех
зависимостей, где это возможно без новых прослоек: Refresher, Embedder,
MarkdownCodec, EmbeddingProvider и аналогичные object-safe интерфейсы.
Способ владения выбирать по реальному жизненному циклу в lib.rs, без Arc,
фабрик и wrapper-структур. Сохранить необходимые generics для scoped Storage,
не-object-safe интерфейсов и связанных типов блокировок.

Плюс: меньше параметров у сервисов при сохранении транзакционного контракта.
Ограничение: Read<'a> и остальные ассоциированные типы остаются, полностью
дженерики не исчезнут. Точные сокращения требуют проверки каждого конструктора
и реального владения зависимостями; не обещаем SearchService без всех параметров.

## Вариант B: обычные интерфейсы возвращаемых транзакций

Storage сразу возвращает объекты через интерфейсы, как в знакомых Java/Go API.
Иллюстрация формы, не готовая реализация:

```rust
pub trait ReadTransaction: StorageRead + GraphRead {}

pub trait Storage {
    fn begin_read_tx(&mut self)
        -> StorageResult<Box<dyn ReadTransaction + '_>>;
}
```

Аналогично CacheWrite/VectorWrite возвращаются через Box<dyn ... + '_>;
commit получает object-safe consuming receiver self: Box<Self>. ReadTransaction
объединяет два существующих read-интерфейса, поскольку Rust не разрешает
написать dyn StorageRead + GraphRead напрямую. Нужна минимальная реализация
этого объединения, без нового runtime или подсистемы.

Плюс: Read<'a>/CacheWrite<'a>/VectorWrite<'a> и storage-associated GAT исчезают;
Storage может использоваться как dyn Storage. Синтаксис '_ сохраняет проверку,
что транзакция не переживает заимствованное хранилище.
Цена: heap allocation для возвращаемого boxed transaction и динамическая
диспетчеризация; consuming commit и места передачи read view надо изменить.
Остальные non-object-safe интерфейсы/lock associated types отдельно проверить,
чтобы не заменить старые generics дополнительными слоями. Производительность
не объявляется неизменной без измерения; сравнительный замер — часть проверки.

## Инварианты для обоих вариантов

Публичный CLI/JSON и схемы БД неизменны. Сохраняются атомарный commit,
rollback при drop/ошибке, эксклюзивное заимствование, pinned read revision,
identity guards и освобождение handles при ранних выходах. Не добавлять async,
Arc, service factories, произвольные callback слои или новые зависимости.

Выбран вариант B. Ассоциированные типы блокировок FileSystem/EmbeddingFiles сохраняются; эта работа меняет именно storage transaction GAT.
