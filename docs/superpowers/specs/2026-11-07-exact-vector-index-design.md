# Exact SQLite vector index acceleration

The user requested implementing vector-index acceleration in SQLite after the
existing no-index/cos behavior was explained. This is a focused continuation of
issue65/search optimization. The coordinator chooses pinned vec1's exact
flat/cos mode; approximate ranking, a candidate cap and changed observation
guarantees are outside the request's implementation scope.

## Retained behavior

- Keep SQLite/rusqlite and pinned native vec1 0.8, synchronous execution, full
  available vector channel, complete eligible-channel RRF and deterministic ties.
- Keep fresh knowledge/source captures and demanded failures beyond final limit.
- Preserve original f32 vector bytes, rowids/search hashes, dimensions, embedding
  identity, error/attempt state and existing pinned read views. No reembedding.
- Preserve read-only status and query-only schema validation. A non-flat
  query-only database stays readable; preparation waits for a writable handle.
- A physical index change does not bump logical schema version or change model
  identity. The index is cache state: no legacy recognition or compatibility
  validation is required, and an incompatible database may be recreated from
  the existing knowledge files.

## Smallest implementation

Change fresh creation and configuration-reset defaults to flat/cos. After ordinary
structural schema bootstrap, compare the opaque persisted model with the model
generated by the same pinned native module on an in-memory reference. The public
`vec1cat` descriptor alone hides unknown distance codes, so it is insufficient.
Perform this on the writable owner before consumer attachments are created.
Already-flat is a read-only no-op.
For any other model, acquire the existing bounded immediate transaction, recheck
the model after contention, execute native rebuild to flat/cos and commit.
Failures roll back. Complete inspection cursors before rebuild/rollback/retry;
never retain native statements across mode changes. The rebuild replaces whatever
non-flat model or state was present; unknown or malformed state is not inspected
or repaired, because the cache is recreatable.

The new flat blocks contain authoritative full-vector payload. They are not a
disposable secondary index. Preserve native insertion/deletion/reset protocols.
Keep the implementation private to storage and synchronize the current schema
mirror; captured historical SQL fixtures and measurements remain unchanged.
The physical preparation and its inline tests have one private owner in
`src/storage/vector_index.rs`; `schema.rs` retains structural schema management.

## Evidence and checks

Native mode comparison uses owned SQLite online backups of the already populated
synthetic100k corpus with real embeddinggemma vectors (768 dimensions). Never
write the original fixture. Measure native SQL separately from complete CLI calls;
do not substitute stored-vector native probes for actual query-provider latency.

Tests independently cover literal ranking/byte/state preservation, idempotence,
new/reset mode, retained dimension after deleting all vectors, query-only/no-op,
non-flat replacement, rollback/retry, competing writers and a separate pinned
reader across rebuild. Mutation-check new behavior tests.
Run actual-root `make verify` through the host storage runner, including native
capability/schema parity and copied executable checks. Record any unavailable
platform rather than claiming cross-platform completion.

Only after those gates retain the candidate, capture source/binary identities,
run three alternating full-CLI pairs serially and record genuine Samply. OS cache
and shared host remain uncontrolled. First-open migration/conditioning is setup,
reported separately from steady-state ordinary latency.

Official context: [vec1 exhaustive modes](https://www.sqlite.org/vec1doc.html),
[rebuild reference](https://sqlite.org/vec1ref.html). Actual behavior is checked
against the pinned vendored source and native experiments, not inferred from a
newer online version. Research, raw attempts and implementation receipts belong
in a new `checks/issue-65/vector-index/` archive, preserving previous evidence.
