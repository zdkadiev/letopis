# Direct-root CPU adapter review

**Verdict: BLOCK for bounded P0 runtime.** Direct Samply launch is the right topology, but the prepared adapter does not yet establish the required attribution identity and mock/vector-state oracles. Review is static only: no tests, product, sampler, CLI or tool probes were run.

## Intrinsic blockers

1. [`direct_root_cpu.py:120–152`](tools/direct_root_cpu.py#L120-L152): profile library matching checks only name and UUID, not the exact private executable path, and `record_attempt` accepts an arbitrary matching binary rather than requiring a verified private copy. Bind the profile library path to the verified private executable, and require/record that private copy plus its matching dSYM. Keep the full 116-input source/build and UUID gates.
2. [`direct_root_cpu.py:138–152`](tools/direct_root_cpu.py#L138-L152): a PID qualifies if any sampled frame maps to the matching library, but the positive `letopis::` CPU check and saved function weights come from **all libraries** in that PID, including fallback names. Positive unrelated-library CPU can satisfy the gate, and no product-library-only weighted counter is saved. Attribute and count positive-weight samples using resolved frames of the exact matching product library; save that counter separately from clearly labeled all-library PID stacks. Derive PIDs from profile metadata, explicitly not an independent OS exec trace.
3. [`direct_root_cpu.py:58–65, 95–117`](tools/direct_root_cpu.py#L58-L65): enabled search setup drains the fixture, but neither before nor after search receives native current-configuration coverage verification. Drain checks provider items against observed queue but does not require initial queue and distinct hashes equal fixture N. Verify and retain native coverage for the **same disposable search database before and after** its query; for drain require N distinct hashes, queue N→0, zero failures, N provider **items**, and native N covered / zero missing / 32 dimensions. Keep provider request counts distinct from items.
4. [`direct_root_cpu.py:129–149`](tools/direct_root_cpu.py#L129-L149): no matching sampled library/PID raises instead of writing an `insufficient` attribution; the documented single 10 kHz diagnostic is conditioned on insufficient output. Preserve raw evidence and classify zero/missing product samples explicitly as insufficient or otherwise make the finite diagnostic eligible, without treating them as zero-cost. A malformed profile or identity mismatch must remain an error, not be relabeled as valid sampling.

## Scope and runtime qualifications

- [`direct_root_cpu_preparation.md:7`](direct_root_cpu_preparation.md#L7) specifies only one invocation for config/help/version; it does not implement the requested bounded 64-iteration read-only groups. Limit iteration grouping to those three commands; search, drain and init remain one fresh-state invocation per capture. Preserve actual observed output/count evidence and do not invent child exit statuses for Samply iteration mode.
- Direct command argv targets the Rust binary immediately after Samply options; the supplied clean driver environment uses a dummy local OpenAI key and numeric-loopback-only provider configuration. Existing `measure_process` provides owned-group cleanup and per-attempt bounds. No wrapper repair or additional framework is required.
- The adapter delegates finite case order, fresh evidence, 600–900-second phase deadline and external combined-disk/free-space guards to the future caller. A caller must record those checks and all missing/failed attempts. Sampler wait4 RSS is not app RSS; no per-app RSS guard may be claimed for these captures.
- Existing `capture.json` correctly leaves direct child exit status and application RSS unavailable rather than substituting the sampler's values. Single-call output validation checks syntax and state, but cannot prove an independently observed child exit.
- Old Python aggregate preparation and four failed window captures remain historical evidence, not fallback execution or proof of zero cost. The 12 successful legacy direct captures are separate evidence.
