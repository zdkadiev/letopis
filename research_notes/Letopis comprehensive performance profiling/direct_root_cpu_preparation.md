# Direct-root CPU follow-up: prepared, not executed

The one-off [adapter](tools/direct_root_cpu.py) is prepared for review and later execution. It does not change the frozen driver. No fixture, mock, product, sampler, build or runtime test was started for this preparation.

## Execution contract

After explicit transfer of exclusive ownership, create a **new** evidence prefix with the reviewed driver's `prepare --sizes 100,10000`, no real export and no 100k stress. Use its manifest and exact case definitions. Instantiate the driver's `LocalProvider` at the manifest port and call `record_attempt` with the corresponding fixture, separate new absolute attempt evidence path, archived debug1 binary, build metadata, full symbolized build receipt, archived native observer, scratch, provider, selected rate and shared monotonic deadline. Caller records exceptions and unattempted cases; never reuse an attempt directory. Use one fresh copy per call. Execute the eight `CASE_IDS` once at 1,000 Hz; only a case with fewer than 100 product stacks gets at most one separately labeled 10,000 Hz attempt. Config, help and version use `--iteration-count 64` with EOF; other cases use one invocation and their own request bytes.

`record_attempt` reuses `prepare_state`, lease, mock, snapshot checks, response and case oracles, and native vector observer. It verifies and copies the executable and dSYM privately per attempt, reverifies their hashes and UUID, then launches Samply with that binary directly using existing `measure_process` and its explicit environment. Capture limit is 4 MiB. `capture.json`, stdout/stderr, profile, sidecar and, when available, validation and attribution are retained separately. Enabled search receives separate native coverage observations of the same disposable database before and after the query. Sampler exit is not recorded as child exit; child exit and product RSS are explicitly unavailable without independent instrumentation. PIDs are derived from matching exact private-path and UUID library frames, not an independent execution trace. Product-library resolved functions are weighted separately from the all-library counters. Function attribution is inclusive and overlapping.

Use a shared phase deadline of at most 600–900 seconds and 120 seconds per call; caller checks free space >=20 GiB and the 4 GiB combined nonbuild soft limit before and after each attempt and records resource stops. No live bound or application RSS guarantee is implied. Preserve old catalog and failed-window captures byte-for-byte. Never run this adapter before the current exclusive drain-scale owner releases the machine.
