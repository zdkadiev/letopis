# Letopis CLI command coverage and behavior contracts

## 1. What commands and workloads must profiling cover?

### Takeaway

Eight public commands exist: `init`, `check`, `inspect`, `search`, `traverse`, `index`, `status`, `config`; ninth executable operation is internal `embed --drain`. Help/version are separate plain-text modes. There are NO `get`, `graph`, `drain`, `help`, `version`, `reindex`, setter, corpus-write, or cancellation-by-PID commands. Treat parser and wiring as implementation authority, not historical design prose. [Parser](../../src/cli/input.rs#L16-L40), [argv dispatch](../../src/cli/input.rs#L158-L205), [help dispatch](../../src/cli/help.rs#L188-L212)

Creates `.letopis/`, cache/vector schemas, default disabled config if absent; preserves existing valid config/data. No indexing, inference, vector reset, or drain. Failure: outside/bare Git, invalid existing config, incompatible/inaccessible schemas, unsafe filesystem. - Input has no `command` wrapper. Most commands read one JSON object through EOF; terminal stdin and silent nonterminal stdin after 250 ms become `{}`. Benchmark using prewritten JSON/closed stdin; otherwise first-byte waiting can dominate tiny commands. No deadline after first byte. Unknown fields rejected. [Contract](../../src/cli/help.rs#L159-L171), [implementation](../../src/process/input.rs#L6-L55), [parser](../../src/cli/input.rs#L409-L437)
- Normal success/error is one JSON line; `ok:true` exit 0, `ok:false` exit 1; help/version plain text exceptions. Error catalog: `invalid_request`, `not_found`, `validation_failed`, `embedding_failed`, `internal_error`, `cancelled`. Classify semantic findings separately from process failures. [Help](../../src/cli/help.rs#L159-L171), [check implementation](../../src/service/check.rs#L79-L80)
- Paths and IDs are repository-root-relative; paths/IDs/type/filter lists deduplicated with ordered sets. Check/index missing paths mean empty set; inspect/traverse empty starts rejected. Explicit optional scalar/object null rejected. [Parser](../../src/cli/input.rs#L49-L99), [paths and IDs](../../src/cli/input.rs#L221-L249), [non-null parser](../../src/cli/input.rs#L374-L389)
- Search default/cap is 100; values >100 clamp, zero/null reject. SQL FTS and exact cosine vec1 channels each return at most L rows; Rust union at most 2L before freshness/filter/fusion. Filters can underfill results; no refill. Internal SQLite scan/workspace can still scale with corpus. Earlier section claiming full eligible candidate ranking is superseded by latest bounded SQL section. [Latest contract](../../docs/zkit/letopis/contracts/X-1-cli.md#L126-L137), [older contradictory section](../../docs/zkit/letopis/contracts/X-1-cli.md#L56-L70)
- Search filters: optional `needs_recheck` bool, `sources` exact canonical source URIs, `source_revisions` full Git tree OIDs. Fields AND; values within lists OR; source+revision must match one binding. All requested revisions checked before inference/empty candidate exit. [Contract](../../docs/zkit/letopis/contracts/X-1-cli.md#L58-L70), [parser](../../src/cli/input.rs#L337-L371)
- Candidate corpus: `.md`/`.markdown`, tracked/untracked per Git/discovery policy, only marked files produce knowledge. Metadata syntax `<!-- letopis: {"created_at":...} -->`; whole-file first-line element or explicit heading anchor plus immediate metadata, no nested elements. Synthetic fixtures must follow syntax or profiling may measure invalid/empty corpus. [Markdown contract](../../docs/zkit/letopis/contracts/X-4-markdown.md#L8-L37)
- Discovery config `discovery.respect_gitignore` defaults true; false admits standard-ignored untracked paths. `.letopis/ignore` applies root-relative Gitignore rules to tracked and untracked candidates; hard exclusions and no-follow remain. Include many nonknowledge Markdown files and ignored candidates as discovery workloads distinct from actual nodes. [Discovery contract](../../docs/zkit/letopis/contracts/X-1-cli.md#L95-L124)
- Architecture's illustrative target: 100k knowledge nodes, conditional 100k sources, 500k edges, up to 10 concurrent agents and ~10 search/s burst target. Warm ~1 s is goal, not timeout/SLO or proven capacity; 1 GiB original local-model budget is not verified. [Architecture targets](../../docs/zkit/letopis/architecture.md#L45-L47)

### Inferences

- Proposed dataset axes (not benchmark measurements): tiny/1k/10k/100k knowledge nodes; fixed nodes with varying owner-file count; varied bytes per element; shared vs unique search_hash; zero/many external source bindings; shallow/deep/shared snapshot roots; chain/star/dense graphs; 1/2/5/10 concurrent CLI processes. These isolate discovery, parsing, SQL, provenance, traversal, and lock costs implied by contracts above.
- Separate foreground latency/CPU/RSS, detached drain cost, and total scenario completion. Parent-only CPU/RSS excludes meaningful background work; querying `status` during busy runs introduces its own diagnostics/provenance cost. Repeated `search` is not automatically a read-only warm-cache benchmark.
- All eight per-command help forms and both combined Full flags require coverage receipts, but no need duplicate expensive profiling for semantically identical mode aliases.

### Gaps

- No timing, CPU, memory, profiler, model availability, runtime failure, or capacity result gathered. This assignment authorizes research only, not builds/installations/benchmarks.
- Comprehensive profiling must choose actual dataset sizes and repetitions based on budget; 100k nodes/500k edges are design targets, not permission to call paid APIs for every element.

## 2. What process, provider, and mutation constraints govern profiling?

### Takeaway

Ordinary `check`/`inspect`/`search`/`traverse` and every `index` mode can publish cache/Git state and trigger detached drain after successful work. `status`/`config`/help/version do not refresh. Use disposable self-contained repositories and explicit disabled config for local-only baselines; OpenAI-only user constraint excludes Ollama even though supported. [Wiring](../../src/commands.rs#L63-L181), [provider contract](../../docs/zkit/letopis/contracts/X-2-embeddings.md#L7-L23)

### Cited Findings

- Every command process is synchronous Rust; no persistent worker or async runtime. Only detached child is executable itself with argv `embed --drain`, CWD repository root, `setsid`, fd 0/1/2 to `/dev/null`; dropped process handle is not waited. Environment inherited (no override in spawn). [Composition](../../src/lib.rs#L642-L657), [process launcher](../../src/process/detached.rs#L31-L55), [architecture](../../docs/zkit/letopis/architecture.md#L64-L78)
- After successful index/check/search/traverse/inspect, `finish_foreground` calls background readiness/work check, probes embed.lock, releases probe, spawns child if free. Probe/spawn errors can become warnings; readiness error can still fail foreground response after primary work committed. Race may spawn losing child; actual drain lock serializes computation. [Finish](../../src/cli/response.rs#L103-L120), [background service](../../src/service/background_runner.rs#L35-L62)
- No CLI switch like `--no-background`, `--fts`, `--model`, `--threads`, `--timeout`, `--format`, or benchmark mode is accepted by parser. FTS/no-inference baseline controlled by config file, not invented flags. [Exact argv grammar](../../src/cli/input.rs#L158-L205)
- New config defaults disabled: `{"embedding_model":{"enabled":false,"provider":null,"model":null,"parameters":{},"max_retries":0}}` plus effective discovery defaults. When existing config absent, `config` returns null; malformed discovery stops refresh even if bad embedding settings alone permit FTS fallback. [Config contract](../../docs/zkit/letopis/contracts/X-1-cli.md#L24-L26), [discovery validation](../../docs/zkit/letopis/contracts/X-1-cli.md#L95-L124)
- Valid disabled model config suppresses inference/reset/drain while retaining vectors/attempts. Enabled readiness identity is hash of provider/model/parameters/max_retries, excluding enabled/discovery; changing those configured fields can transactionally recreate vec1 and clear vector keys/failures. `status` deliberately observes without resetting identity. Config toggles are not equivalent to deleting vector state. [Readiness contract](../../docs/zkit/letopis/contracts/X-1-cli.md#L26-L26), [embedding contract](../../docs/zkit/letopis/contracts/X-2-embeddings.md#L21-L32)
- Product supports `openai` compatible protocol and `ollama` native. For this study user permits only OpenAI models: select `provider:"openai"` and verified OpenAI endpoint/model; compatible protocol alone does NOT establish that upstream model is OpenAI. Explicit `parameters.base_url` includes API prefix (`https://api.openai.com/v1` example), client appends `/embeddings`. User restriction is stronger than supported product surface. [Provider boundary](../../docs/zkit/letopis/contracts/X-2-embeddings.md#L7-L16)
- `OPENAI_API_KEY` read once from process environment; drain inherits key from launcher. No `.env` or hot rotation; credentials forbidden in parameters, outputs/evidence must not expose key. Code creates both protocol HTTP agents locally even when no model request occurs. [Composition](../../src/lib.rs#L691-L702), [provider construction](../../src/embedding/provider.rs#L94-L105), [credential contract](../../docs/zkit/letopis/contracts/X-2-embeddings.md#L14-L16)
- HTTP per-attempt deadline 60 s; redirects and environment proxy discovery disabled; TLS platform verification; bounded response 10 MiB. No user-facing timeout setting or whole-search cutoff. Query failure FTS fallback is successful response and singleton persisted query_error; cannot infer successful embedding solely from exit 0. [Transport](../../src/embedding/provider.rs#L14-L16), [HTTP config](../../src/embedding/provider.rs#L45-L89), [fallback contract](../../docs/zkit/letopis/contracts/X-2-embeddings.md#L20-L30)
- Drain computes one text per request, reserves durable attempts before HTTP, one-second retry delay, max total attempts `1+max_retries`; stale hashes skipped per invocation; no-work path prunes unreferenced vectors and attempt records. Include reserve/write/prepare costs and retries in measured workload; repeated runs can have exhausted work. [Mechanics](../../docs/zkit/letopis/mechanics.md#L121-L139), [service constants/calls](../../src/service/embedding.rs#L13-L15), [single-text request](../../src/service/embedding.rs#L444-L453)
- Index lock serializes publication; embed lock serializes drain. Routine unchanged refresh can avoid index lock only when published, delta empty, and no retained source roots; verified/full always take it. Consequently “unchanged” with source bindings can differ substantially. [Mechanics locking](../../docs/zkit/letopis/mechanics.md#L380-L385)
- SIGINT handler installed for **all exact accepted index modes**, plus exact search/traverse/inspect/check; other argv/default commands use default signals. This is more complete than historical prose mentioning only full index/reindex. Handler before stdin/services, cancellation JSON exit 1; detached drain no installed handler. [Parser truth](../../src/cli/input.rs#L125-L140), [entry contract](../../src/lib.rs#L121-L139)
- No corpus-write commands. Refresh/index mutate `.letopis/cache.db` and SQLite sidecars, file projections, graph, FTS, revision; source retention/inspect can write Git objects and retention refs; readiness/drain mutate vectors and failures, lock files/PIDs persist. Never benchmark against author’s production `.letopis` or Git store. [Markdown ownership](../../docs/zkit/letopis/contracts/X-4-markdown.md#L6-L8), [publication](../../docs/zkit/letopis/mechanics.md#L75-L95), [source audit](../../docs/zkit/letopis/contracts/X-1-cli.md#L22-L26), [locks](../../docs/zkit/letopis/mechanics.md#L198-L222)
- Git snapshots require self-contained repo: object alternates rejected even if inactive/empty; no lazy-fetch or Git executable fallback in product. Avoid shared/reference clone fixtures. [Composition API](../../src/lib.rs#L704-L725), [repository guidance](../../AGENTS.md#L105-L106)

### Inferences

- To exclude background interference, use valid disabled model config in disposable fixtures; to isolate enabled query overhead, prefill vector coverage and verify no pending drain. An externally held embed lock could suppress spawning but changes observed lock/contention state; label such experiments explicitly.
- Network wall time and remote model CPU/RAM are different quantities: local CLI sampling cannot measure OpenAI service CPU/RAM. Report remote service resource usage unavailable rather than attributing provider delay to Rust CPU.
- Capture snapshots/clones per mutable scenario and restore from isolated fixture copies, not reset author worktree or delete real databases. Warm runs must assert resulting revision/backlog/vector identity/work remaining.

### Gaps

- OpenAI credentials, permitted model, quota/cost budget, actual endpoint availability, profiler entitlement, and selected sample rate remain unverified.
- No supported env bypass for background discovered in parser/composition; tests contain LETOPIS_* markers, not a documented production benchmark control.
