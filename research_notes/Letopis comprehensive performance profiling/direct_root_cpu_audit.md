# Direct-root CPU evidence audit

**PASS, qualified.** Fifteen actual captures cover eight categories: six usable and nine insufficient under the recorded ≥100 product-library-stack and positive resolved Letopis CPU rule. This audit read saved evidence and recomputed hashes, outputs and stack weights; no tests, product, profiler or measurement probes ran.

- All 15 raw profile and sidecar hashes match [verification.json](evidence/direct-root-cpu-20261117-v1/verification.json). All 15 private executables and adjacent dSYM artifacts match the symbolized build receipt hashes; all **116** recorded source inputs match current bytes. For captures with sampled product frames, profile metadata matches the exact private executable path and UUID `FFEBF8EC-A110-37A6-AA8B-747F67DAEA21`; matching sidecars carry the same code ID. The 1 kHz version capture has no matching sampled product library and is correctly **insufficient**, not an identity error or zero CPU.
- Independently traversed raw frames, symbol sidecars and CPU deltas reproduce the reported product-library-only function counters, matching-library-derived PIDs, stack counts, all-library observed-CPU denominators and usable/insufficient classification for all captures where a product library appeared. PIDs derive from profile frames, not an independent OS execution trace.

## Limits and closeout

These are instrumented profiles, not stock-baseline latency, per-child exit traces, real-provider performance, exclusive CPU costs or an application RSS guard. Profile counts and function proportions from one capture per case are not confidence intervals. The four older window captures remain preserved but unattributable; the Python aggregate wrapper was never executed. No additional experiment is authorized by this audit. Research is frozen for report synthesis.
