## Blocking findings in round-one changes

1. **Source identity incomplete — `:116-118,156-158,1231-1261`.** Preparation records `HEAD`, and build verification compares that string with the compilation metadata while hashing only `metadata["input_hashes"]`. The supplied `evidence/build_metadata.json` pins only five files: Cargo manifest/lock, toolchain, build script and vec1 source—**no `src/` files**. A modified or untracked Rust product file at the same HEAD is accepted and can be attributed to the old binary/revision. The archived stock/symbolized `build.json` receipts contain the complete 116-input mapping; verify the matching full product input inventory and current revision/dirty state against the relevant receipt before validation and measurement, including added/deleted product inputs.
2. **Soft disk gate misses existing evidence during setup — `:216,262-280,1117-1123`.** The pre-slot check counts scratch plus the evidence root, but the post-copy check passes `directory` (only the current receipt directory), omitting all other evidence. If the copy pushes combined scratch+evidence over 2 GiB while scratch+current receipt remains below it, setup and measured product work continue despite the required post-copy guard. Pass the actual evidence root and stop before product launch; retain a clear resource-stop receipt.
3. **RSS stop is bypassed for setup failures and profile children — `:245-249,295-308,344-358,1277-1292`.** Setup checks RSS only *after* parsing/validating output; a failed or timed-out setup with observed RSS ≥1 GiB raises before the threshold check, and subsequent cases can run. Profile rows expose wrapper RSS, while the product's wait4 peak is nested in the window child receipt and never used for `resource_stop`; wrapper RSS is not a substitute for product RSS. Inspect each available observed product/setup peak before outcome-dependent parsing and stop later slots even on failure/censor; keep missing RSS explicitly unavailable. This requests the agreed **post-sample** rule, not a hard/live watchdog.
4. **Coverage summary conflates skips and successful censored profiles — `:920-934`.** `coverage.successful` counts every `is_valid` row, including a usable **censored** profile, while `coverage.invalid` counts `validation_gate_skipped`, `series_stopped`, `profile_limit_skipped`, and `resource_stop_skipped` as invalid attempts. It also pools validation, conditioning, profile and baseline by case. `account_plan` distinguishes these states, but the adjacent coverage report can still present false success/failure counts. Partition by stage/phase and report attempted, complete success, censored, skipped, setup-failed and missing separately; do not count a usable censored capture as a completed command.
